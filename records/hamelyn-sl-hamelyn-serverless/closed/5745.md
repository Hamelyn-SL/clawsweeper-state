## Summary

Conviene mantener abierta esta incidencia porque `dev` todavía conserva tres accesos a Amazon Catalog API fuera del limitador y el PR que los corrige sigue abierto, aunque ya está limpio y aprobado.

## What This Changes

Corregir el throttling 429 de Amazon Catalog API que puede agotar reintentos y dejar creates sin ASIN.

## Best Possible Solution

Todos los accesos conocidos deben compartir el presupuesto de Catalog API y los chunks agotados deben quedar visibles como fallo parcial; tras estabilizar el PR actual, solo debería añadirse coordinación distribuida si producción demuestra que el límite por proceso sigue siendo insuficiente.

Sí, con alta confianza a nivel de fuente y evidencia de producción: `dev` mantiene tres llamadas fuera del limitador y existe un incidente documentado con reintentos agotados y 16 creates sin ASIN. No se ejecutó una reproducción local contra Amazon.

## Solution Assessment

Sí como primera fase: aplicar el limitador existente a todos los accesos conocidos es la corrección más estrecha y reversible. La coordinación distribuida debe quedar condicionada a métricas posteriores al despliegue, no introducirse de antemano.
