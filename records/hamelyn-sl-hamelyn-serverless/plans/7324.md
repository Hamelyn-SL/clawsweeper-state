# Coding Plan for hamelyn-sl/hamelyn-serverless#7324: Ecommerce: las nuevas incidencias llegan vacías al listado de eDesk

Source report: [records/hamelyn-sl-hamelyn-serverless/items/7324.md](records/hamelyn-sl-hamelyn-serverless/items/7324.md)

## Summary

Mantendría abierta esta issue: en `dev` sigue existiendo el fallo central, porque el cliente compartido de eDesk no reintenta `429` y el pipeline de incidencias puede registrar el ticket como éxito aunque falle el mensaje. La actualización operativa con BigQuery convierte el problema en pérdida operativa de mensajes, no en una mejora opcional.

## Plan

Arregla la issue de eDesk `429` en incidencias: añade retry/backoff acotado en `packages/core/src/infrastructure/external-apis/edesk/edesk.service.ts` para `POST /tickets` y `POST /messages`, respetando `Retry-After` si existe y sin retry infinito. Ajusta `packages/core/src/application-services/incidents/create-edesk-incident.ts` para que, si el mensaje no se crea tras agotar reintentos, no devuelva `{ ok: true }` ni provoque un falso `201`; preserva el dump `[INCIDENT_CONTENT_DUMP]` y define una respuesta de error que permita recuperación operativa sin duplicar tickets accidentalmente. Revisa consumidores en ecommerce, Supply y búsqueda de pedido; no cambies UI ni reestructures flujos no relacionados. Añade cobertura o un script local de verificación focalizado para fallo transitorio `429`, éxito tras retry y agotamiento de reintentos.
