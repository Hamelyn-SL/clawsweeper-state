## Summary

Mantener abierta: en el `dev` actual no existe un `operationType` Skypod en productividad y la UI de estación todavía no inicia ni actualiza una sesión propia de productividad.

## Plan

Implement the station-specific Skypod productivity feature for this issue only. Add a `SKYPOD`/Estación Skypod productivity operation through the shared core enum, admin enum, productivity config labels/descriptions/metadata/count key/start route/metric units, `/v4/admin/opProductivity` metadata sanitization/merge/counting, and the Admin station preparation lifecycle. In station preparation mode, start or require an active Skypod productivity session using the existing `ProductivityHeader`/session pattern, increment processed items on successful positive ACK/OK confirmations, and end/pause cleanly when leaving preparation. Preserve existing operation types and do not implement the broader Picking/Packing subtype model from https://github.com/Hamelyn-SL/hamelyn-serverless/issues/5822. Do not change unrelated station bridge behavior. If exception actions need to count, keep that as an explicit, isolated choice in the PR notes rather than silently changing existing `not-found` semantics.
