## Summary

La funcionalidad sigue pendiente en `dev`: Ecommerce usa Next.js 16.3, pero no activa Cache Components y el layout raíz sigue dependiendo de `headers()` por petición.

## What This Changes

La issue propone migrar Ecommerce a Cache Components de Next.js 16.3 para lograr navegación instantánea sin cachear datos dependientes de visitante, disponibilidad o precio.

## Best Possible Solution

Aprobar una migración por fases: inventario de rutas y datos, piloto en páginas públicas sin estado de visitante, y después pruebas de preview que cubran fresh install funcional y dominios regionales.

- **Mantener el modelo actual:** Conservar las cachés de datos actuales y priorizar optimizaciones puntuales de TTFB sin cambiar el modelo de renderizado.

No hay una reproducción ejecutada de alta confianza; el código confirma la dependencia de request del layout y la ausencia de Cache Components, pero faltan mediciones runtime de TTFB y navegación.

## Solution Assessment

No como un único cambio global: la dirección es válida, pero la solución mantenible exige una matriz de cacheabilidad y un piloto que preserve los datos dinámicos.
