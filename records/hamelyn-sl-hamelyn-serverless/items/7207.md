## Summary

La reparación funcional parece encaminada, pero el PR aún no debería cerrarse ni darse por listo: el head actual conserva un riesgo de seguridad concreto al pasar la contraseña E2E como `EXPO_PUBLIC_*`, lo que Expo inyecta en el bundle de cliente. Además, el cuerpo afirma que `Supply E2E Tests` pasó, pero en el contexto disponible no hay enlace, log, captura o artefacto positivo verificable del head final.

## What This Changes

El branch modifica Supply E2E para usar Node 22, añadir artefactos de Maestro, exponer `navbar_index_link`, sustituir el login UI por bootstrap ROPC en modo E2E y quitar `hideKeyboard` de flows Maestro.

## Best Possible Solution

Mantener la reparación E2E, pero sacar la contraseña del bundle Expo: obtener o inyectar el token desde el runner/Device Cloud mediante una vía solo-test no pública, y adjuntar prueba positiva del head final con datos privados redactados.
