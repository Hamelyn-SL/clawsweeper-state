## Label Justifications

- `P1`: El cron de producción reintenta repetidamente el mismo mensaje y genera errores operativos recurrentes durante el procesamiento de pedidos Amazon.
- `impact:other`: El problema afecta a la fiabilidad del cron y a la creación controlada de pedidos, sin evidencia de pérdida de mensajes ni caída completa del proceso.

## Summary

La incidencia sigue siendo necesaria: `dev` aún convierte un SKU inexistente en un pedido no formateado, devuelve `canDelete: false` y retiene la notificación para reintento. No existe una PR abierta que cubra este caso; la coordinación debe pasar por la persona ya asignada.

## What This Changes

Evitar que `amazon-notifications-pull` retenga indefinidamente una notificación `ORDER_CHANGE` cuando el SKU de la orden ya no existe en stocks.

## Best Possible Solution

Representar explícitamente el resultado de formato por pedido y convertir solo el SKU confirmado como inexistente en una salida terminal auditable —preferiblemente un `OrderSell` `TO_CANCEL` válido o, si el dominio no lo permite, dead-letter y alerta única— manteniendo el retry para fallos transitorios.
