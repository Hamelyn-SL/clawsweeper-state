## Label Justifications

- `P2`: Es una mejora de infraestructura acotada con impacto real en seguimiento de PRs, pero no bloquea producción ni un flujo crítico.
- `impact:message-loss`: La issue trata eventos de review, merge y cierre que actualmente no generan mensajes en el canal de PRs.
- `impact:ux-friction`: El estado de una PR no se puede ver de un vistazo en Slack sin abrir GitHub o reconstruir el contexto manualmente.

## Summary

La issue sigue siendo necesaria: en `dev` las PRs aún se notifican a Slack con webhook suelto y no existe el script con bot token, KV, hilo y reacción de estado que pide la aceptación.

## What This Changes

Unificar las notificaciones de PR en `#github-noty` usando un mensaje raíz por PR, replies por eventos de review/cierre/merge y una reacción de estado reconciliada.

## Best Possible Solution

Añadir un `notify-prs-slack.js` paralelo al notificador de issues, migrar `pr-lifecycle.yml` a bot token con KV/thread/reacciones, ampliar eventos de cierre y review, y dejar `pr-review-reminder.yml` separado.
