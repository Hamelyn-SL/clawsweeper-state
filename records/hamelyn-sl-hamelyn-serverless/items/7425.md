## Label Justifications

- `P1`: La pérdida de campos de eDesk afecta a un flujo operativo activo de atención al cliente, pero todavía falta evidencia de ticket concreto para tratarlo como emergencia reproducida.
- `impact:data-loss`: El reporte trata de metadatos operativos de tickets que pueden perderse o quedar omitidos al crear la incidencia en eDesk.
- `impact:ux-friction`: ATC puede tener que reconstruir enlaces de seguimiento, admin y Stripe manualmente cuando los campos personalizados no aparecen.

## Summary

No propongo cerrar este issue: `dev` construye los campos personalizados de Ecommerce y conserva un fallback que puede crear el ticket sin campos si eDesk rechaza `custom_fields`, pero la captura y la investigación previa aún no vinculan el caso a un ticket concreto ni demuestran que ese fallback se haya activado en Ecommerce.

## What This Changes

El issue reporta que algunos mensajes de Ecommerce creados en eDesk pierden campos personalizados con enlaces de seguimiento, admin y Stripe.

## Best Possible Solution

Mantener el issue abierto hasta revisar tickets concretos afectados; con esa evidencia, decidir si basta con ajustar el fallback para preservar los campos en el `bodyHtml` o si hay una causa operativa dentro de eDesk fuera del código.
