## What This Changes

La issue solicita reservar `TO_CANCEL` para rechazos inequívocos y mantener pendientes o reintentables las confirmaciones dropshipping ambiguas o transitorias.

## Best Possible Solution

Mantener una fase `PENDING_PROVIDER_CONFIRMATION`, persistir de forma segura el resultado antes de habilitar otro intento y exigir reconciliación o comprobación del proveedor para cualquier caso sin garantía idempotente.

Rationale: El SLA y la política de retry deciden cuándo cancelar una venta cobrada y cuándo asumir riesgo de duplicación externa; el contrato actual de Azeta y Arnoia no resuelve esa elección.

Likely owner: MarcosTerroso

Owner confidence: high

Options:

- **Estado intermedio y retry seguro (recommended):** Adoptar el estado propuesto, automatizar solo los fallos inequívocamente seguros y dejar los ambiguos para reconciliación manual.
- **Sin retries hasta reconciliar:** Mantener todos los fallos no concluyentes en revisión manual hasta disponer de una referencia idempotente o consulta fiable por proveedor.
- **Conservar cancelación inmediata:** Mantener la salida común a `TO_CANCEL`, aceptando cancelaciones incorrectas para evitar cualquier posible pedido duplicado.
