## Summary

La issue sigue siendo necesaria, pero no como una nueva corrección de `updatePipeline`: la ruta actual ya pasa `updatePipeline: true` y los selectores vigentes no reintroducen esta cohorte `SYNC_ERROR/UNKNOWN` en el procesamiento de batches. Permanece una reconciliación operativa específica de Fnac cuya seguridad depende de contrastar el estado remoto antes de modificar miles de documentos históricos.

## What This Changes

La issue solicita distinguir y reconciliar la cohorte histórica de Fnac en `SYNC_ERROR` que conserva la firma de `updatePipeline` tras corregirse el productor.

## Best Possible Solution

Ejecutar un dry-run sobre la firma exacta, contrastar varios `batchId` y ofertas Fnac con la API remota, y aplicar después una reconciliación masiva limitada, auditable y aprobada que deje cada documento en el estado coherente con el resultado remoto.
