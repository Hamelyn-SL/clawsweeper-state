## Label Justifications

- `P0`: El defecto mantiene una vía directa para acceder o mutar datos de carrito de otra persona.
- `merge-risk: 🚨 security-boundary`: La ruta de creación autenticada puede reutilizar un carrito ajeno sin verificar posesión.
- `merge-risk: 🚨 compatibility`: La expiración de la ventana legacy cambia el acceso a carritos anónimos ya existentes.

## Summary

Mantener abierta: el cambio deja un bypass de autorización para un usuario autenticado sin carrito propio, por lo que puede recibir o modificar un carrito ajeno indicando su `cartId`.

## What This Changes

El PR añade capabilities en cookies para carritos anónimos y autorización con JWT de Auth0 para los carritos vinculados a usuarios.

## Best Possible Solution

Hacer que la creación sólo devuelva un carrito recién creado y, ante una colisión de ID, volver a cargarlo y exigir la autorización correspondiente antes de leerlo o mutarlo.

- **Exigir capability de inmediato:** Cerrar el acceso legacy al desplegar y aceptar que los invitados afectados creen un carrito nuevo.

## Solution Assessment

No: el guard es adecuado para carritos ya cargados, pero la rama de creación debe impedir que un ID existente eluda ese guard.
