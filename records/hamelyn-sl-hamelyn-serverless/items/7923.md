## Summary

El enfoque de capability/JWT es adecuado, pero el PR aún permite leer o modificar el carrito ajeno cuando un usuario autenticado no tiene carrito propio; debe corregirse antes de mergear.

## What This Changes

El PR añade capabilities en cookie para carritos anónimos, autorización JWT para carritos de usuario y elimina la identidad aportada por el cliente en las rutas v5 de ecommerce.

## Best Possible Solution

Separar de forma estricta creación y búsqueda: si un `cartId` válido ya existe, autorizarlo antes de devolverlo o mutarlo; crear sólo tras confirmar su inexistencia y cubrir ambos casos con pruebas de ruta.

Required: false

## Reproduction Assessment

Sí, por inspección de fuente: con un JWT válido de un usuario sin carrito propio y el `cartId` de otro carrito existente, los fallbacks de GET y POST reutilizan ese ID sin autorización.

## Solution Assessment

No todavía: el guard común es una buena dirección, pero el fallback de creación debe rechazar colisiones existentes antes de exponerlas o mutarlas.
