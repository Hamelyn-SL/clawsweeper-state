## Summary

La incidencia sigue siendo necesaria: el flujo actual aísla el 404 por batch, pero deja las filas en `BATCH`, por lo que el selector las vuelve a consultar indefinidamente.

## What This Changes

Terminalizar los batches Amazon cuyo processing report ya no existe para detener el polling permanente y conservar un motivo auditable.

## Best Possible Solution

Convertir únicamente el 404 confirmado de `Feeds.getFeed` en un error terminal con `retryPolicy: PERMANENT`, preservando batch, report y causa; reparar la cohorte histórica con un script local idempotente separado.

## Solution Assessment
