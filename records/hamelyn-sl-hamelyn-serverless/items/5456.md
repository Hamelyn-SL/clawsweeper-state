## Summary

Mantener abierta para decisión de comportamiento: la mitigación fusionada aisló scopes, pero `create` aún persiste el error y corta los chunks restantes ante rate limit. La evidencia reciente no demuestra nuevas respuestas remotas, así que no procede otro arreglo automático.

## What This Changes

La incidencia pide evitar que un rate limit de `create` de TodoColeccion corte el lote de productos y propague degradación dentro del cron.

## Best Possible Solution

Definir una política explícita para 429 reales de TodoColeccion: cuota observada, backoff acotado, condición de reanudación y aislamiento entre create y precio, con señal operacional estructurada.

Options:

- **Mantener el corte conservador (recommended):** Conservar el `break` actual y reabrir una reparación solo con una respuesta 429 reciente y datos de cuota del proveedor.
- **Introducir recuperación acotada:** Añadir backoff y reanudación limitados por cuota confirmada, preservando el breaker para evitar ráfagas.
- **Separar create de precio:** Usar scopes distintos para reducir el impacto cruzado dentro de `products`, definiendo antes la semántica de recuperación.

## Solution Assessment
