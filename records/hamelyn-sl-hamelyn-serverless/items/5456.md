## Summary

Keep open: current `dev` contains the scoped breaker mitigation from the merged follow-up PR, but the issue was reopened with the same create-side rate-limit signature and the current code still aborts the TodoColeccion create batch on 429/Too Many responses.

## What This Changes

TodoColeccion create requests hit provider rate limits, open the products circuit breaker, and stop the current create batch inside `/api/todoColeccion`.

## Best Possible Solution

Define a TodoColeccion products-write policy from live response data, then implement a narrow products-scope throttle, lock, or time-budgeted create queue that prevents repeated 429s while keeping unrelated phases isolated and visible.
