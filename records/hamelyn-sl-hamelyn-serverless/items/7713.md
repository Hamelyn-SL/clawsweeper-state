## Summary

El PR sigue siendo necesario: `dev` todavía genera dos operaciones sobre el mismo `purchasable_offer` cuando se desactiva repricing. El parche propuesto concentra correctamente esa retirada en el update directo y el feed batch, mientras que la alta conserva `add`; antes del merge falta una prueba positiva posterior al cambio que valide explícitamente esa expectativa.

## What This Changes

El PR sustituye los dos parches incompatibles de precio y retirada de repricing de Amazon por un único `merge` para listings existentes y actualiza la documentación operativa asociada.

## Best Possible Solution

Conservar `add` para la creación inicial y demostrar con un harness ejecutado sobre el HEAD que los updates directo y batch sin repricing emiten exactamente un `merge` con precio, umbrales y plan a `null`, sin alterar las altas.

Sí, por inspección de código: en `dev` las rutas directa y batch construyen un `replace` y un segundo `merge` para el mismo `purchasable_offer`. La incidencia relacionada además aporta respuestas reales de Amazon con `InvalidInput: Conflicting operation`.

## Solution Assessment

Sí, la consolidación en un único `merge` para updates existentes es la solución más acotada para la restricción de Amazon; la creación debe conservar `add` porque el atributo todavía no existe tras `putListing`.
