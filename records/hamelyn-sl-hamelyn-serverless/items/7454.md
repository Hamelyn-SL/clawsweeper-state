## Summary

Debe seguir abierto: el código actual permite cancelar un lote recibido, pero los flujos automáticos que he encontrado no cubren con claridad el caso reportado de `PICKED_UP`/recibido que luego aparece cancelado o expirado en eDesk.

## What This Changes

El issue reporta que el lote `01MAY_786HA` aparece cancelado en eDesk/admin pero sigue en estado recibido.

## Best Possible Solution

Definir la fuente de verdad para cancelaciones tardías de lotes ya recibidos y, si eDesk debe prevalecer, añadir una transición acotada a `CANCELLED` con auditoría y cobertura de regresión.

Options:

- **Cancelar si eDesk confirma expirado (recommended):** Tratar eDesk/cancelación como fuente de verdad para este caso y añadir una regla acotada que pase el lote a `CANCELLED` con auditoría.
- **Mantener recibido como final logístico:** Dejar `PICKED_UP` como estado prevalente tras entrega y resolver el caso mediante corrección operativa puntual si eDesk está desalineado.

## Reproduction Assessment

No tenemos una reproducción de alta confianza con datos reales. Sí hay una ruta reproducible por código: los lotes `PICKED_UP` o con `ENTREGADO` quedan fuera del cron de tracking y la cancelación tardía no parece aplicar automáticamente.

## Solution Assessment

Aún no está claro que una corrección automática sea la mejor vía sin confirmar negocio. La solución más mantenible es acotar primero si eDesk/cancelación debe ganar sobre la recepción física del lote.
