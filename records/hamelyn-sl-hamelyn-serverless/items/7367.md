- `impact:other`: Una región omitida puede conservar ofertas obsoletas o vendibles después de que su stock haya sido retirado.

## Summary

Debe seguir abierta: `dev` todavía permite que una nueva región Amazon se incorpore sin una garantía exhaustiva para la retirada masiva, y el PR vinculado que intenta corregirlo continúa abierto y en conflicto tras las altas de Amazon FR e IT.

## What This Changes

Centralizar la capacidad de retirada masiva de Amazon en una configuración tipada y exhaustiva compartida por el registry, el factory y el cron.

## Best Possible Solution

Mantener una única tabla exhaustiva `Record<AmazonMarketplaceCode, ...>` con factories perezosos y cliente de batch withdraw, iterarla una vez desde el cron y cubrir inclusión de todas las regiones, exclusión de proveedores no Amazon, selección par/impar y continuidad controlada ante errores.

Required: false

## Reproduction Assessment

Sí, con alta confianza desde fuente: las incorporaciones de Amazon FR y la propuesta de Amazon IT requieren editar manualmente clientes, tipos y llamadas dentro de `amazonMethodBatchWithdraw`, mientras las pruebas del registry no cubren esa obligación.

## Solution Assessment

Sí en cuanto a dirección arquitectónica: derivar el flujo desde una configuración exhaustiva y perezosa es la solución más estrecha y mantenible; el PR actual necesita actualizarse frente a `dev`, añadir cobertura específica y demostrar el comportamiento operativo.
