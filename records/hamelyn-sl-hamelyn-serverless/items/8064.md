## Label Justifications

- `impact:ux-release-blocker`: El flujo afectado no ofrece una recuperación clara dentro del producto y muestra una clave técnica literal.

## Summary

El defecto sigue presente en `dev`: el carrito optimista anónimo recibe un ID distinto del persistido y checkout valida el cupón con ese ID local. La reparación concreta está en una PR abierta, por lo que esta issue debe permanecer abierta hasta su revisión e integración.

## What This Changes

Corregir la divergencia de IDs del primer carrito anónimo y mostrar un mensaje traducido cuando la validación del cupón no encuentra el carrito.

## Best Possible Solution

Integrar una reparación que reutilice y reconcilie el ID persistido, y confirmar mediante el flujo anónimo sin recarga que el cupón y su mensaje de error funcionan correctamente.

## Reproduction Assessment

Sí, con alta confianza desde código: iniciar un carrito anónimo, añadir el primer producto sin recargar y validar un cupón hace que checkout use el ID optimista distinto del persistido.

## Solution Assessment

Sí. La corrección candidata modifica el único constructor divergente, reconcilia el ID que devuelve la API y cubre la clave de traducción ausente; es una solución acotada al contrato actual.
