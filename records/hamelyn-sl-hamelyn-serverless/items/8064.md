## Label Justifications

- `P0`: Un comprador anónimo queda bloqueado al aplicar una promoción durante checkout, sin recuperación visible dentro del producto.
- `impact:ux-release-blocker`: La compra no puede continuar con el cupón anunciado porque el checkout usa un carrito que la API no reconoce.

## Summary

El defecto sigue vigente en `dev`: el primer carrito anónimo conserva dos IDs y checkout valida el cupón contra el ID optimista inexistente; además, el mensaje de error carece de traducción.

## What This Changes

La incidencia pide reutilizar el ID persistido en el carrito optimista, reconciliar la respuesta del alta y traducir `invalidCartError` en checkout.

## Best Possible Solution

Mantener un único `cartId` desde el alta optimista, reconciliar el ID devuelto por API y añadir la traducción en los 13 locales junto con cobertura de regresión.
