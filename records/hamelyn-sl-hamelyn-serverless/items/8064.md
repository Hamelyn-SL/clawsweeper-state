## Label Justifications

- `P0`: Bloquea a compradores anónimos durante el checkout al impedir aplicar una promoción anunciada.
- `impact:ux-release-blocker`: La ruta de compra no ofrece recuperación visible cuando el cupón falla por un ID de carrito inconsistente.

## Summary

El defecto sigue presente en `dev`: el primer alta optimista de un carrito anónimo guarda un `cartId`, pero crea el estado local con otro ObjectId. Checkout valida el cupón usando ese segundo ID y el endpoint devuelve `invalidCartError`.

## What This Changes

Corregir la divergencia entre el `cartId` optimista y el persistido para que los cupones funcionen en carritos anónimos recién creados, y traducir el error de carrito.

## Best Possible Solution

Hacer que el carrito optimista use el `cartId` solicitado, reconciliar el `cartId` devuelto por la API y añadir `invalidCartError` a todos los diccionarios de checkout.

## Solution Assessment

Sí. Reutilizar y reconciliar el ID persistido elimina la consulta a un carrito inexistente sin cambiar el contrato de cupones.
