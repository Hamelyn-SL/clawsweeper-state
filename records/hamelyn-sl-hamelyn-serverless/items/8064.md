## Summary

El defecto sigue presente en `dev`: el primer carrito anónimo conserva dos IDs y checkout valida el cupón con el ID optimista inexistente. No hay una PR abierta que cubra esta corrección.

## What This Changes

Reutilizar el `cartId` persistido en el carrito optimista, reconciliar la respuesta del alta y traducir `invalidCartError` en checkout.

## Best Possible Solution

Mantener un único ID desde el alta optimista hasta checkout, aceptar el ID devuelto por la API y añadir la traducción en todos los locales antes de validar la regresión sin recarga.
