## Label Justifications

- `P2`: El defecto cambia la construcción de términos de búsqueda, pero tiene un arreglo localizado y no bloquea el uso general de ecommerce.
- `impact:ux-friction`: Consultas visualmente equivalentes copiadas desde otras aplicaciones pueden normalizarse de forma distinta.

## Summary

La incidencia sigue vigente en `dev`: `normalizeSearchText` aún separa solo por espacios ASCII. La PR vinculada aporta el cambio acotado, pruebas y prueba diferencial suficiente, pero permanece abierta y sin integrar.

## What This Changes

La incidencia solicita que la normalización de búsquedas ecommerce trate cualquier secuencia de whitespace como separador antes de descartar términos cortos.

## Best Possible Solution

Integrar la corrección estrecha de https://github.com/Hamelyn-SL/hamelyn-serverless/pull/7987 tras el flujo habitual de revisión; así todas las consultas con whitespace equivalente producirán los mismos términos.

Sí, a nivel de código con alta confianza: `normalizeSearchText("el\tcasa")` conserva el término corto porque la implementación actual usa `.split(" ")`. No se ejecutó el flujo para preservar el checkout de revisión en solo lectura.

## Solution Assessment
