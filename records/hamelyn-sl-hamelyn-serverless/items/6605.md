## Summary

La automatización solicitada sigue siendo necesaria: la rama por defecto `dev` genera y almacena etiquetas de Mercado Libre y dispone de envío SMTP, pero no programa ni envía el correo diario. Además, la selección segura no está definida porque la integración todavía no reconcilia cancelaciones posteriores al alta del pedido.

## What This Changes

Se solicita enviar automáticamente de lunes a viernes las etiquetas diarias de Mercado Libre al contacto operativo en México, excluyendo las ventas canceladas.

## Best Possible Solution

Definir una selección canónica basada en API o estado interno reconciliado con Mercado Libre, excluir cancelaciones de forma verificable, combinar las etiquetas individuales en PDF y enviarlas mediante un cron idempotente de lunes a viernes con destinatario, zona horaria, hora de corte y activación configurables.

Options:

- **Origen interno reconciliado (recommended):** Procesar primero cancelaciones y cambios de Mercado Libre, definir el corte diario y automatizar después el correo con idempotencia y auditoría.
- **Envío asistido desde admin:** Añadir una pantalla que previsualice pedidos y etiquetas elegibles y requiera confirmación humana antes de enviar el correo.
- **Mantener proceso manual:** Cerrar la petición si el coste de reconciliar pedidos y operar una automatización fiable no compensa el ahorro operativo.

## Reproduction Assessment

No aplica como reproducción de un fallo: se solicita una capacidad nueva. La inspección de la rama `dev` confirma que existen las piezas de etiquetas y correo, pero no el flujo automático completo.

## Solution Assessment

No, automatizar la navegación de Mercado Libre no es la solución más mantenible. La vía segura es usar la API y el estado interno tras resolver la reconciliación de cancelaciones, con una previsualización manual como alternativa de menor riesgo.
