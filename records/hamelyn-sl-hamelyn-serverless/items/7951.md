## Summary

La incidencia sigue siendo necesaria: `dev` conserva un job que acepta la petición sin esperar el estado terminal, y el PR abierto que declara resolverla aún requiere validación de staging.

## What This Changes

Corregir PR Proof para que el workflow espere el resultado terminal del mismo run y publique evidencia causal y verificable sin ejecutar configuración no confiable.

## Best Possible Solution

Completar el rollout v2 con la App y credenciales en staging, repetir un canario que alcance estado terminal y habilitar el gate requerido solo tras verificar identidad, SHA y evidencia publicada.
