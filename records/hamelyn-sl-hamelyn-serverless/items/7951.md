- `impact:security`: La autoridad de evidencia y el aislamiento de código no confiable forman una frontera de integridad y seguridad.

## Summary

El problema central sigue abierto: `dev` conserva un workflow que declara éxito tras un HTTP 202, mientras la solución integral está en una PR abierta y el canario de staging aún falla con HTTP 403.

## What This Changes

Corregir PR Proof para que el gate espere un estado terminal con evidencia trazable, identidad por ejecución y aislamiento seguro al instalar código de una PR.

## Best Possible Solution

Validar en staging la identidad y el alias del despliegue, conservar el body de cualquier 403 y aterrizar el workflow v2 solo tras un canario terminal verificable.
