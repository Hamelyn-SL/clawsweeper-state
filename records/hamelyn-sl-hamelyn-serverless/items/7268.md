## Label Justifications

- `P1`: El flujo de soporte de Supply para incidencias de lote queda roto para usuarios sin sesión en una ruta pública recién expuesta.
- `impact:auth-provider`: La incidencia trata de redirigir correctamente a Auth0/login antes de abrir el perfil de ventas.
- `impact:ux-friction`: El usuario puede quedar en una ruta de ventas sin sesión en vez de recibir una acción clara para iniciar sesión y continuar.

## Summary

Conviene mantener esta issue abierta: en `dev` el CTA “Problemas con un lote” de la página pública de contacto navega a `routes.profile.sales`, pero la lista de ventas no lanza el login cuando el usuario no está autenticado.

## What This Changes

La petición pide que, desde `https://hamelyn.com/contacto`, el CTA “Problemas con un lote” redirija a inicio de sesión si el usuario no tiene sesión iniciada.

## Best Possible Solution

Proteger el acceso a Mis ventas en Supply: si el usuario no está autenticado, mostrar o lanzar el login de Auth0 con retorno a `/profile/sales`; si ya lo está, mantener la navegación actual y el flujo de incidencias por lote.

## Reproduction Assessment

Sí por inspección de código: `support_sales_card` navega a `routes.profile.sales` sin auth guard, y la lista de ventas intenta cargar datos sin mostrar login. No lo he reproducido en navegador con una sesión real.

## Solution Assessment

Sí: el arreglo más mantenible es reutilizar el patrón existente de `loginWithRedirect` con `returnTo` o añadir un guard equivalente en la pantalla de ventas, sin crear un canal de soporte nuevo.
