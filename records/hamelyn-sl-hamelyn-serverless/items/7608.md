## Summary

Este PR sigue siendo necesario y está vinculado a la issue canónica, pero no está listo para merge: la redelivery puede volver a ejecutar el mismo intento contra el carrier, superando el límite funcional declarado, y falta prueba de comportamiento real.

## What This Changes

El PR añade reintentos automáticos selectivos y acotados para fallos transitorios de creación de etiquetas, junto con validación del payload, selección de pedidos, pruebas y documentación operativa.

## Best Possible Solution

Separar la recuperación de publicación del efecto externo —o persistir qué intento ya fue ejecutado— para que una redelivery pueda reenviar el retry pendiente sin volver a llamar al carrier, manteniendo un máximo real de tres retries por pedido.

## Solution Assessment

No todavía. Reencolar únicamente IDs retriables es una frontera adecuada, pero usar la redelivery para recuperar un fallo de publicación vuelve a ejecutar el efecto externo y rompe el límite funcional de tres retries.
