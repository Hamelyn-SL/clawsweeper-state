## Label Justifications

- `P2`: El fallo afecta una acción concreta de edición del perfil y no hay evidencia de indisponibilidad generalizada.
- `impact:data-loss`: La foto solicitada por el vendedor se descarta sin persistirse mientras otros cambios pueden guardarse.
- `impact:ux-friction`: La interfaz puede confirmar éxito aunque la foto no haya cambiado.

## Summary

La incidencia sigue siendo necesaria: `PUT /api/v4/profile` elimina la foto cuando falla la subida, persiste el resto y devuelve `204`; Supply y Ecommerce tratan esa respuesta correcta como éxito visible.

## What This Changes

Devolver un error explícito cuando la subida de una foto de perfil falle, sin descartar el cambio silenciosamente.

## Best Possible Solution

Hacer fallar de forma atómica la actualización que incluya una foto no subida, conservar el perfil previo y adaptar ambos clientes para mostrar el error real; actualizar la spec y añadir cobertura de regresión del write-path.

Sí, a nivel de código con alta confianza: una subida que devuelva `undefined` sigue la rama que elimina `picture`, persiste el resto y responde `204`. No se ejecutó una subida real contra Vercel Blob en esta revisión de solo lectura.

## Solution Assessment

Sí. Un error HTTP explícito antes de persistir, junto con clientes que rechacen la respuesta no correcta, es el límite más pequeño que preserva la intención del vendedor y evita éxitos falsos.
