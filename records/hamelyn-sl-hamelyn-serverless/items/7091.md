- `P2`: El fallo descarta una actualización concreta de perfil sin afectar a la disponibilidad general del servicio.
- `impact:data-loss`: La foto solicitada por el vendedor se pierde silenciosamente del update persistido.

## Summary

La incidencia sigue siendo necesaria: `dev` descarta la foto cuando la subida no devuelve URL y responde éxito, mientras los clientes de perfil no convierten el fallo HTTP en una señal de error para el vendedor.

## What This Changes

La incidencia solicita que `PUT /api/v4/profile` informe el fallo de una nueva foto de perfil en vez de eliminarla silenciosamente del cambio.

## Best Possible Solution

Devolver un error explícito antes de persistir cuando falle una foto nueva, hacer que ambos clientes lo propaguen a su UI y actualizar la spec BL con una prueba de regresión del write-path.
