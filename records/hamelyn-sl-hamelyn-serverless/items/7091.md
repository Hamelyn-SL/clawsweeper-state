## Label Justifications

- `P2`: La actualización de perfil se descarta silenciosamente, con alcance limitado pero comportamiento incorrecto para usuarios reales.
- `impact:data-loss`: El cambio solicitado por el vendedor para su foto no se persiste y la respuesta no lo comunica.

## Summary

La issue sigue siendo necesaria: el `dev` actual elimina `picture` cuando falla la subida y devuelve `204`, por lo que el intento del vendedor queda descartado sin una señal fiable de error.

## What This Changes

La issue solicita informar el fallo de subida de la foto de perfil en `PUT /api/v4/profile` en vez de ignorarlo como una actualización satisfactoria.

## Best Possible Solution

Hacer atómico el cambio de foto: si Blob falla, no persistir esa petición, devolver un error estructurado y actualizar Supply y ecommerce para mostrar el fallo al vendedor.
