## Summary

La PR aborda un fallo real de sincronización, pero la nueva guarda descarta eventos de reviewer mientras otro run sigue vivo; ese evento puede ser el único que refleje una asignación tardía en Slack. Requiere una reparación mecánica y prueba real actualizada antes de mergear.

## What This Changes

La rama añade refresco de tarjetas raíz de PR en Slack ante cambios de reviewer, persiste el header junto al `ts`, evita duplicados de run y documenta el ciclo operativo.

## Best Possible Solution

Serializar los runs por PR sin cancelar ni descartar eventos, para que cada cambio de reviewer se ejecute después del anterior, y demostrar un refresh real de una tarjeta existente.
