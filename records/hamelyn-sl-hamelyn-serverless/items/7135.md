## Summary

Debe seguir abierta: el defecto sigue presente en `dev` y hay una PR abierta con sintaxis de cierre que actúa como candidata de solución, pero aún no está fusionada.

## What This Changes

El issue pide que el checkout recalcule y persista desde servidor el descuento de cupón para todos los tipos, no solo para `FREE_UNITS`.

## Best Possible Solution

Fusionar una corrección acotada que use el `discount` validado por servidor para todos los cupones válidos, conservando `unitsGranted` solo como dato específico de unidades gratis y aportando prueba real o staging del flujo de checkout.

## Reproduction Assessment

Sí: la inspección de `dev` muestra que el checkout solo sustituye el descuento del cliente cuando existe `unitsGranted`, mientras la validación devuelve `discount` sin `unitsGranted` para cupones no `FREE_UNITS`. No he ejecutado un checkout real en staging.

## Solution Assessment

Sí: la corrección más estrecha es reconciliar siempre con `couponValidation.discount` cuando el cupón es válido, dejando `unitsGranted` como campo opcional específico de unidades gratis. La PR candidata apunta a ese diseño, pero necesita resolver conflicto y prueba de comportamiento antes de cerrar el issue.
