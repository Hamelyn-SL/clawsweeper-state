## What This Changes

The issue requests server-side reconciliation of checkout coupon discounts for all coupon types instead of trusting the client-sent `appliedDiscount` outside `FREE_UNITS` coupons.

## Best Possible Solution

Review and land https://github.com/Hamelyn-SL/hamelyn-serverless/pull/7157 or an equivalent narrow checkout fix that always stores the server-validated coupon discount while keeping `unitsGranted` specific to `FREE_UNITS`.

## Maintainer Decision

Required: false

## Reproduction Assessment

Yes by source inspection: checkout copies client `appliedDiscount` and only overwrites it when `couponValidation.unitsGranted` exists. The validation utility already computes `discount` for the other coupon types without `unitsGranted`.

## Solution Assessment

Yes, the linked PR is the narrowest apparent fix: use `couponValidation.discount` whenever the coupon is valid, and only persist `unitsGranted` when validation returns it.
