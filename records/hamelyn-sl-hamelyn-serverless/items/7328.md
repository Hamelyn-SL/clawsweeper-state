## Summary

Mantener abierta: la señal productiva es concreta y `dev` no demuestra que Fnac deje de reciclar `Product not found` como error de batch; el código actual incluso conserva rutas que pueden volver a meter errores `STALE` en el pool de retry.

## What This Changes

La issue pide evitar que stocks de Fnac con `Product not found` queden reintentándose indefinidamente como `BATCHING_TO_MARKETPLACE`.

## Best Possible Solution

Implementar una ruta canónica para Fnac `Product not found`: mantenerlo fuera del retry rápido indefinido y, en el reintento `STALE`, crear/validar el producto o marcar el stock como no publicable/retirado con prueba productiva acotada.
