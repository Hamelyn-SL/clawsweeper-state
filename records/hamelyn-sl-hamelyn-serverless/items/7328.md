## Summary

Mantener abierta: `dev` conserva la clasificación `STALE` para `Product not found` de Fnac y el barrido la vuelve a promocionar a `TRANSIENT`, mientras la integración activa solo reenvía ofertas por EAN y no ejecuta recuperación de catálogo. La corrección mínima parece clara, pero elegir entre marcar el error como permanente o construir recuperación de catálogo exige una decisión explícita de marketplace/core.

## What This Changes

La incidencia solicita impedir que los errores Fnac `Product not found` sigan reintentándose como `BATCHING_TO_MARKETPLACE` sin una vía real de recuperación.

## Best Possible Solution

Acordar que `Product not found` sea `PERMANENT` mientras no exista una recuperación real de Catalog API, añadir cobertura focalizada al clasificador y tratar la cohorte existente mediante una intervención de datos independiente y aprobada; si se quiere mantener recuperabilidad, implementar primero el flujo de catálogo y demostrarlo en producción.
