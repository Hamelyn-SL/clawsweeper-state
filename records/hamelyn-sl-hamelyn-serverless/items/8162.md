## Label Justifications

- `P1`: Los errores de sincronización Amazon afectan listings reales en varias regiones y se reproducen en el flujo compartido actual.
- `impact:other`: El impacto principal es la creación regional incorrecta de listings y su repetición en `SYNC_ERROR`, fuera de las clases más específicas.

## Summary

La incidencia sigue siendo necesaria: `dev` colapsa candidatos y reutiliza un ASIN global en seis rutas regionales; faltan la política de ambiguos, compatibilidad legacy y rollout seguro.

## What This Changes

La incidencia solicita reemplazar el uso global de ASIN por una identidad Amazon regional que preserve candidatos y evite contaminaciones entre catálogos.

## Best Possible Solution

Introducir una fuente única por `(EAN, marketplaceId)`, conservar los escalares legacy temporalmente y activar la lectura regional tras shadow mode, validación de schemas y canarios reversibles.

Options:

- **Contrato regional con shadow mode (recommended):** Persistir candidatos y estados por región, bloquear ambiguos y activar por fases después de validar schemas y un canario reversible.
- **Mantener el scalar global:** Conservar el flujo actual mientras se acepta que un ASIN regional puede contaminar las demás ejecuciones.
- **Aislar solo libros inicialmente:** Aplicar la nueva identidad únicamente a `ABIS_BOOK` y posponer las demás familias hasta completar su matriz de schemas.

## Reproduction Assessment

Sí, a nivel de código: basta ejecutar dos regiones con el mismo EAN y candidatos distintos para observar la preferencia por `stock.asin` y la persistencia global. Falta una ejecución productiva controlada para cuantificar el caso concreto.

## Solution Assessment

No del todo: separar la identidad regional es la dirección correcta, pero retirar el ASIN sugerido o imponer reglas globales antes de validar schemas y compatibilidad legacy sería prematuro.
