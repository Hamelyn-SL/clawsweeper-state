## Label Justifications

- `P0`: La propuesta corrige un IDOR que permite leer o mutar carritos Supply ajenos.
- `merge-risk: 🚨 compatibility`: El requisito de capability cambia el comportamiento de sesiones existentes y puede bloquear carritos con estado local incompleto.
- `merge-risk: 🚨 security-boundary`: La rama redefine la autorización de lectura, mutación y asociación de carritos Supply.

## Summary

El PR aborda una vulnerabilidad real, pero aún deja a usuarios con `cartId` persistido y capability perdida sin una ruta para crear un carrito nuevo; además, la transición legacy conserva una decisión de seguridad que debe confirmarse antes del merge.

## What This Changes

El PR sustituye la autorización por `cartId` de los carritos Supply por capabilities hasheadas, crea un merge autenticado y adapta el cliente Supply para almacenar y enviar el token.

## Best Possible Solution

Cerrar el IDOR con capabilities, recrear de forma explícita un carrito cuando una capability protegida se pierde y acordar una transición legacy que no dependa de la posesión pública de `cartId`.

- **Ventana legacy acotada (recommended):** Mantener la fecha de corte actual, documentar el riesgo y añadir recuperación automática cuando el cliente pierda su capability.
- **Migración con prueba adicional:** Conservar legacy sólo si existe una señal de posesión adicional que permita emitir la capability sin basarse únicamente en `cartId`.
