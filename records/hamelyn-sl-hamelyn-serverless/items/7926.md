## Label Justifications

## Summary

El PR sigue siendo necesario, pero mantiene una excepción IDOR para carritos legacy asociados y puede dejar un carrito de reemplazo sin asociar tras una recuperación; no es seguro fusionarlo todavía.

## What This Changes

El PR introduce capabilities hasheadas para carritos Supply, un merge autenticado y compatibilidad temporal para clientes nativos anteriores.

## Best Possible Solution

Exigir capability para todo carrito asociado y definir un rollout verificable para builds antiguas; además, asociar siempre el carrito de reemplazo antes de permitir nuevas altas autenticadas.

Rationale: La excepción preserva clientes nativos instalados, pero mantiene explícitamente el acceso no autorizado que motivó esta corrección; decidir el nivel de compatibilidad aceptable requiere autoridad de producto y seguridad.

- **Proteger primero los carritos asociados (recommended):** Mantener compatibilidad solo para carritos legacy anónimos o mediante un gate de versión, evitando que un `cartId` autorice datos de un usuario.
- **Aceptar la ventana temporal:** Conservar el contrato dual completo hasta el deadline y aceptar explícitamente el riesgo de exposición durante ese periodo.
- **Pausar el despliegue de la migración:** No fusionar hasta disponer de una actualización o rollout que elimine la dependencia de los clientes antiguos.
