## Summary

El objetivo de seguridad es correcto, pero el cliente queda bloqueado cuando conserva `cartId` y pierde o caduca la capability; debe recuperarse creando un carrito nuevo antes de integrar.

## What This Changes

El PR protege los carritos Supply con capabilities hasheadas, elimina `userId` del cliente y sustituye el merge por una ruta autenticada que rota el token.

## Best Possible Solution

Mantener el guard de capabilities y, ante un 404 de acceso, limpiar de forma segura la pareja persistida y crear un carrito nuevo; documentar después el contrato completo de rutas, almacenamiento y rate limit.

## Maintainer Decision

Required: false

## Reproduction Assessment

Sí. Con un `cartId` protegido persistido y sin token, `getCart` recibe 404 y los llamadores retornan sin limpiar ni crear un carrito nuevo.

## Solution Assessment

No todavía. La capability es la solución adecuada al IDOR, pero necesita una recuperación explícita y segura para capacidades perdidas y carritos legacy tras el corte.
