## Label Justifications

- `P0`: Un despliegue puede dejar bloqueado el flujo central de carrito de usuarios con builds Supply ya instaladas.
- `merge-risk: 🚨 compatibility`: La diff sustituye operaciones históricas sin capability por un token obligatorio y elimina `PUT`.
- `merge-risk: 🚨 security-boundary`: La autorización de todas las operaciones de carrito cambia de posesión de ID a capability y JWT.

## Summary

El PR sigue siendo necesario para cerrar el IDOR, pero no es seguro fusionarlo: rompe el contrato de builds Supply desplegadas, no recupera capabilities perdidas y rota el token en cada alta autenticada.

## What This Changes

El PR protege los carritos Supply con capabilities hasheadas, elimina `userId` del contrato HTTP y añade un merge autenticado con Auth0.

## Best Possible Solution

Mantener la capability como límite de autorización, pero desplegarla con una transición compatible verificable, recuperación de token por propietario autenticado y reinicio seguro para anónimos.
