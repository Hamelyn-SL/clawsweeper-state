## Label Justifications

- `P1`: La creación de nuevas ofertas eBay está deshabilitada como mitigación de un fallo recurrente de producción.
- `impact:other`: El impacto es inventario que no se publica y una señal agregada de salud engañosa, sin una categoría específica más adecuada.

## Summary

Mantener abierta: `dev` sigue absorbiendo como éxito HTTP los fallos parciales de publicación y `ebay.create()` está deshabilitado como mitigación temporal, por lo que la publicación de nuevas ofertas y su señal operativa no están resueltas.

## What This Changes

Corregir el flujo de publicación masiva de eBay para diagnosticar los fallos por oferta y evitar que un lote sin publicaciones correctas aparente una ejecución saludable.

## Best Possible Solution

Clasificar los rechazos remotos por oferta y SKU, preservar el código y mensaje de eBay, rechazar explícitamente la fase create/publish cuando no se publique ninguna oferta y reactivar `ebay.create()` solo tras una prueba operativa controlada.

## Maintainer Decision

Required: true

Kind: product_direction

Question: ¿Qué contrato debe tener `/api/ebay` cuando la fase create/publish termina con cero ofertas publicadas?

Rationale: El código demuestra el fallo y la mitigación, pero no determina si debe fallar toda la respuesta HTTP, solo la fase de publicación con alerta, o conservar HTTP 200 por compatibilidad.

Likely owner: MarcosTerroso

Owner reason: Introdujo la mitigación operativa vigente y tiene historial directo en create y reconciliación de ofertas eBay.

Owner confidence: high

Options:

- **Rechazar la fase create (recommended):** Hacer que el fallo total rechace create/publish, aparezca en `executionSummary` y active una alerta, sin cambiar la política de otras fases o marketplaces.
- **Mantener HTTP 200 reforzado:** Conservar la respuesta HTTP actual, pero exigir una métrica y una alerta operativa específica cuando `successfulPublications` sea cero.
- **Cambiar el wrapper global:** Devolver un estado HTTP no exitoso ante cualquier rechazo parcial de cualquier cron, asumiendo el impacto transversal.

## Reproduction Assessment

Sí, con confianza alta a nivel de fuente: las respuestas fallidas de `bulkPublishOffer` terminan como errores de stock, el wrapper conserva HTTP 200 y create está deshabilitado como mitigación. No existe una reproducción viva normal desde el cron mientras `ebay.create()` siga comentado.

## Solution Assessment

No. Añadir más logs es necesario, pero la solución mantenible también debe clasificar los errores por oferta, definir la señal de fallo total y demostrar una reactivación segura de create.
