## Summary

Keep open: current dev still has the bulkPublishOffer partial-response path and the common cron wrapper still reports HTTP 200, while the active eBay cron only mitigates the problem by disabling create. The merged policy-retry change for https://github.com/Hamelyn-SL/hamelyn-serverless/pull/5779 helps one observed eBay rejection family but does not finish the per-offer observability or zero-success batch signal requested here.

## What This Changes

The issue asks for eBay bulkPublishOffer failures to expose per-offer error detail and avoid being hidden behind a successful marketplace-cron response when a publish batch has zero successful publications.

## Best Possible Solution

Re-enable eBay create only after bulk publish returns actionable per-offer diagnostics and zero-success publish batches produce the agreed operational signal without hiding failed publication behind a healthy cron result.

Yes for the core behavior: current source still returns parsed partial bulkPublishOffer responses, maps failed publications into stock errors, and the shared cron wrapper returns HTTP 200 for partial failures. ## Solution Assessment

No, the current state is not the final fix: disabling create avoids the failing path, and the merged policy classification only handles one rejection family. The narrow maintainable solution is to add per-offer publish diagnostics plus the agreed zero-success batch signal before re-enabling create.
