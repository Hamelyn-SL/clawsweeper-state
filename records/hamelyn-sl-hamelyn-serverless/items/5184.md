## Label Justifications

- `P1`: La reactivación pendiente de create bloquea una sincronización eBay fiable y el contrato actual puede ocultar rechazos materiales.
- `impact:other`: El impacto principal es la observabilidad y la capacidad operativa de detectar una ejecución degradada del cron.

## Summary

Mantener abierta: `ebay.create()` sigue pausado y, si se reactiva, los rechazos de publicación aún acabarían en una ejecución HTTP `200`; falta acordar una señal operativa compatible antes de recuperar esa fase.

## What This Changes

La incidencia pide que los rechazos de `bulkPublishOffer` en eBay queden identificados y no aparezcan como una ejecución sana del cron.

## Best Possible Solution

Definir bajo https://github.com/Hamelyn-SL/hamelyn-serverless/issues/5622 una señal estructurada por ruta y reactivar `ebay.create()` solo con trazas por SKU/error y una comprobación controlada de publicación.

## Maintainer Decision

Required: true

Kind: product_direction

Question: ¿Qué señal debe emitir `/api/ebay` al reactivar create cuando un lote de `bulkPublishOffer` falla parcial o totalmente: HTTP compatible más severidad estructurada, o un estado HTTP degradado por ruta?

Rationale: El handler es compartido por varios crons y los comentarios de la canónica muestran que una modificación global de HTTP puede romper flujos que continúan deliberadamente ante fallos permanentes.

Likely owner: JavierHamelyn

Owner reason: Ha documentado la necesidad de una política transversal y mantiene historial reciente en la integración eBay.

Owner confidence: medium

Options:

- **Señal estructurada compatible (recommended):** Mantener temporalmente HTTP `200`, añadir estado y severidad consultables por ruta, y fijar un umbral explícito para eBay antes de reactivar create.
- **Degradar eBay por ruta:** Hacer que los fallos completos de publicación en eBay devuelvan un estado degradado, aceptando el impacto operativo documentado para esa ruta.

## Reproduction Assessment

No en producción: `ebay.create()` está desactivado en el controlador actual. Sí por código: una respuesta no 2xx de `bulkPublishOffer` se convierte en error de creación sin hacer que el handler abandone su HTTP `200`.

## Solution Assessment

No del todo: el flujo ya conserva detalles por oferta y SKU; lo pendiente es decidir la severidad y la señal por ruta, no aplicar un cambio global de estado HTTP sin contrato.
