## Label Justifications

- `P2`: El trabajo manual recurrente de almacén afecta a consolidados pesados, pero no hay evidencia de caída generalizada ni pérdida de datos.
- `impact:ux-friction`: El personal de almacén necesita intervención manual para evitar errores de peso y generar etiquetas de consolidados.

## Summary

Mantener abierta: `dev` conserva el cambio manual Spring→FEDEX multibulto y ya evita imprimir por duplicado una etiqueta consolidada, pero no resuelve el flujo central de routing por destinatario ni el aplazamiento de etiquetado hasta que almacén indique las cajas.

## What This Changes

La solicitud propone enrutar consolidados pesados de prep-centers a FEDEX, aplazar su etiquetado hasta packing y generar etiquetas multibulto sin duplicarlas.

## Best Possible Solution

Definir una fila ShipMatrix con matcher de destinatario y un estado explícito de consolidado pendiente de cajas; después permitir que packing genere o regenere una única expedición FEDEX multibulto por `consolidationId`, con confirmación y deduplicación de impresión.

- **Limitarlo a una regla temporal de dirección:** Crear una regla de ShipMatrix para el destino actual sin generalizar el modelo hasta validar más prep-centers.
