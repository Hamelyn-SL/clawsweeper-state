## Label Justifications

- `P2`: Es una mejora normal del ecommerce que reduce fricción de soporte, pero requiere decisión de producto/seguridad antes de desarrollo.
- `impact:ux-friction`: Los compradores guest pueden comprar sin cuenta pero hoy deben abrir una incidencia genérica para pedir una cancelación gestionada manualmente.

## Summary

Mantener abierta: en `dev` sigue faltando el autoservicio guest para cancelar pedidos; el flujo guest actual solo verifica pedido/email para crear incidencias y la cancelación real sigue dependiendo de sesión Auth0.

## What This Changes

Se solicita permitir que compradores guest del ecommerce cancelen pedidos con verificación por `codeIdentifier` + email, reutilizando la lógica de cancelación existente y ofreciendo incidencia cuando el pedido ya no sea cancelable.

## Best Possible Solution

Aprobar primero el contrato de producto/seguridad y después implementar un helper server-side común de cancelación, una ruta guest con Zod, rate limit, validación `codeIdentifier` + email, comprobación de estados cancelables y una UI en `ContactHelpCenter` que permita cancelar o continuar con incidencia.
