## Summary

Debe seguir abierta: en `dev` aún no existe cancelación guest y la única salida para invitados sigue siendo abrir una incidencia. La feature es viable, pero añade una mutación pública sensible y necesita decisión de producto/seguridad antes de automatizar un PR.

## What This Changes

La issue pide permitir que compradores guest cancelen pedidos desde ecommerce usando `codeIdentifier` + email, con la misma elegibilidad que la cancelación logueada.

## Best Possible Solution

Definir y construir un flujo guest propio: endpoint con Zod, verificación `codeIdentifier` + email, rate limit, comprobación server-side de estados cancelables y UI que permita cancelar o continuar con incidencia.
