## Summary

Mantener abierta: en `dev` sigue sin existir autoservicio guest para cancelar pedidos; el flujo guest actual solo valida datos para abrir una incidencia y la cancelación real sigue detrás de sesión Auth0.

## What This Changes

La issue pide permitir que compradores guest de ecommerce cancelen pedidos con verificación `codeIdentifier` + email, reutilizando la lógica de cancelación existente y manteniendo el flujo de incidencia como fallback.

## Best Possible Solution

Extraer una acción server-side común de cancelación ecommerce, llamarla desde sesión y desde una ruta guest con Zod, rate limit, 404 indistinguible y comprobación de `PENDING_PICKING`/`PENDING_LABEL`, y actualizar `ContactHelpCenter` para ofrecer cancelar o abrir incidencia según elegibilidad.
