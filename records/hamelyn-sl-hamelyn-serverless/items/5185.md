## Summary

La issue sigue siendo necesaria: `dev` ya recupera fallos transitorios y reconcilia listings remotos cerrados, inactivos o inexistentes, pero los `400` genéricos cuyo listing continúa activo siguen acabando como `SYNC_ERROR` sin una política de recuperación. El comentario del 16 de julio confirma además un backlog vivo de 4.316 SKUs; la política HTTP global se trata por separado en https://github.com/Hamelyn-SL/hamelyn-serverless/issues/5622.

## What This Changes

Clasificar los errores HTTP 400 genéricos de `updatePrice` de MercadoLibre, decidir su tratamiento según el estado remoto y preparar el drenaje seguro del backlog afectado.

## Best Possible Solution

Conservar la reconciliación actual para listings stale y añadir una clasificación específica de los `400` activos basada en la respuesta estructurada y/o una consulta remota; después, ejecutar un dry-run y un backfill acotado que trate cada resultado como transitorio, permanente o inactivo.
