## Summary

El fallo sigue presente en `dev`: las PR humanas se agrupan por autor aunque la siguiente acción sea una revisión. Una PR abierta y vinculada implementa la corrección, por lo que esta issue debe seguir abierta hasta que se revise y se integre.

## What This Changes

Corregir el recordatorio de PRs en Slack para agrupar cada PR por la persona responsable de la siguiente acción.

## Best Possible Solution

Integrar una única derivación de `actionOwner` que use reviewer pendiente, autor o solicitante de cambios según el estado y los commits posteriores.
