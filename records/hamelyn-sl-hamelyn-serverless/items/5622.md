## Label Justifications

- `P1`: Los fallos parciales repetidos pueden pasar inadvertidos para alertas y operaciones que interpretan HTTP 2xx como éxito.
- `impact:other`: La afectación principal es la observabilidad operativa transversal de los cron jobs.

## Summary

La incidencia sigue siendo necesaria: el handler App Router ya devuelve un resumen de rechazos, pero mantiene HTTP 200 para cualquier fallo parcial y no define una severidad común ni una señal analítica consultable.

## What This Changes

Definir un contrato común de severidad y observabilidad para que los rechazos parciales de cron no queden ocultos tras respuestas HTTP 200.

## Best Possible Solution

Acordar una taxonomía compatible de `ok`, `partial_failure` y `failed`, emitirla en ambos handlers y escalar a 207/5xx solo en las rutas clasificadas como críticas.
