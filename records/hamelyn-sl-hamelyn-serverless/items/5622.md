## Summary

Keep open: current dev still returns HTTP 200 for partial cron-handler failures, and the issue remains a real product/operations policy decision rather than stale cleanup.

## What This Changes

The issue requests an explicit cron-handler partial-failure policy and structured operational signal so degraded cron executions are not hidden behind HTTP 200 responses.

## Best Possible Solution

Define a compatible first phase that emits structured `partial_failure`/`failed` signals while preserving HTTP 200 by default, then add route-specific 207/5xx behavior only after maintainers classify expected versus alertable partial failures.
