## Summary

Mantener abierta: en `dev` el checkout todavía puede conservar el badge de cupón aplicado cuando la revalidación devuelve `valid: false`, y la corrección está en una PR abierta que todavía no se ha mergeado.

## What This Changes

La issue pide que el checkout retire el estado visual de cupón aplicado o muestre un aviso claro cuando la revalidación automática invalida el cupón por cambios de carrito o envío.

## Best Possible Solution

Revisar y mergear `https://github.com/Hamelyn-SL/hamelyn-serverless/pull/7193`; después la issue podrá cerrarse por la referencia de cierre de GitHub o por verificación en `dev`.

Required: false

## Reproduction Assessment

Sí, por inspección de código: una respuesta `valid: false` durante la revalidación automática deja `appliedCoupon` intacto porque `keepAppliedCoupon=true`, mientras la UI muestra el badge por la mera presencia de `appliedCoupon`. No he ejecutado el checkout real en navegador.

## Solution Assessment

Sí: la solución más estrecha es limpiar `appliedCoupon` solo cuando el backend confirma una invalidación de negocio, preservando la tolerancia ante errores técnicos como propone la PR abierta.
