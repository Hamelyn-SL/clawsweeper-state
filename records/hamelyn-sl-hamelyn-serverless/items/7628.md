## Label Justifications

- `P2`: El ajuste se guarda correctamente, pero la confirmación oculta y el cambio temporal de tamaño degradan un flujo de perfil con alcance limitado.
- `impact:ux-friction`: El usuario puede dudar de si el cambio se guardó y repetir la acción porque el mensaje queda detrás del panel.

## Summary

La issue sigue siendo necesaria: `dev` conserva el toast de éxito fuera del `Modal` de Ajustes y el callback llamado `hideModal` no cierra el panel, por lo que el síntoma descrito sigue siendo coherente con el código actual. Es una corrección UX pequeña y delimitada, sin otro issue o PR que la esté cubriendo.

## What This Changes

Corregir la confirmación al guardar Ajustes del Perfil en Supply web para que aparezca delante del panel y no altere el tamaño de la página.

## Best Possible Solution

Mantener un único sistema de confirmación y hacer que el toast web se renderice como overlay o portal por encima del `Modal`, sin reservar altura ni provocar reflow; además, renombrar o corregir `hideModal` si su contrato real debe cerrar el panel.
