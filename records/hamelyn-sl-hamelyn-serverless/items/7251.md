## Review Findings

Overall correctness: patch is incorrect

Overall confidence: 0.9

Full review comments:

- **[P1] Serializa el refresh del token antes de activar crons:** `apps/agents/agent/lib/codex-token.ts:193-194`
  - body: `getAccessToken()` y el cron `refreshIfNeeded()` pueden leer el mismo token y llamar a `refresh()` en paralelo. Como el `refresh_token` es de un solo uso, una carrera puede invalidar el token almacenado y dejar sin responder a todos los agentes; usad un lock distribuido o compare-and-swap sobre Blob antes de refrescar.
  - confidence: 0.93
- **[P1] Aísla mongo_script fuera del runtime de la app:** `apps/agents/agent/tools/mongo_script.ts:110-114`
  - body: El script aprobado se ejecuta con `new Function` dentro del proceso de Next, así que puede alcanzar `process.env`, `fetch` y cualquier global además de `db`/`params`. Para una herramienta con escritura en producción, esto necesita un worker/proceso aislado o una API de operaciones acotadas antes de merge.
  - confidence: 0.9
- **[P2] Tolera reviews sin usuario en el asignador:** `apps/agents/agent/pr-reviewer/github.ts:129-130`
  - body: La API de GitHub puede devolver reviews cuyo `user` es `null` si la cuenta fue eliminada o no está disponible. Este acceso directo a `r.user.login` tumbaría el reviewer agent y bloquearía la asignación automática en esos PRs.
  - confidence: 0.86
- **[P3] Rellena siempre el número objetivo de reviewers:** `apps/agents/agent/pr-reviewer/decide.ts:204-210`
  - body: Después de filtrar logins no elegibles, se devuelve `valid.slice(0, targetReviewers)` aunque `valid.length` sea menor que el objetivo. En PRs grandes configurados para dos reviewers, el bot puede pedir solo uno sin error ni reintento.
  - confidence: 0.82
