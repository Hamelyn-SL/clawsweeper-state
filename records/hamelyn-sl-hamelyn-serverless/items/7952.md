## Label Justifications

- `P1`: Una URL de catálogo manipulada deja resultados existentes inaccesibles en una ruta principal de compra.
- `impact:ux-friction`: El contador y el estado vacío se contradicen, obligando al usuario a corregir manualmente la URL.

## Summary

La incidencia sigue vigente en `dev`: SSR normaliza `page`, pero el cliente vuelve a parsearla sin respaldo y puede solicitar `page=NaN`. La PR abierta vinculada concentra la corrección, por lo que cerrar o abrir otra reparación duplicaría trabajo.

## What This Changes

Normalizar valores inválidos de `page` en el catálogo para conservar los resultados SSR después de la hidratación.

## Best Possible Solution

Integrar una normalización única que acepte únicamente enteros decimales positivos y seguros, aplicarla a SSR, cliente, canonical y consulta, y validar el flujo real tras hidratar.

## Reproduction Assessment

Sí, desde código con alta confianza: abrir el catálogo con `page=abc` hace que SSR use 1 y el cliente use `NaN`; no se ejecutó un navegador durante esta revisión.

## Solution Assessment

Sí, con el límite de validar estrictamente el entero antes de compartirlo entre capas; una sola función evita que SSR, hidratación y consulta diverjan.
