## Label Justifications

- `P1`: Una URL de catálogo malformada puede ocultar resultados existentes a usuarios de ecommerce, aunque el alcance queda limitado a parámetros de paginación inválidos.
- `impact:ux-friction`: La pantalla muestra un contador válido junto al estado vacío y obliga al usuario a corregir manualmente la URL para continuar.

## Summary

La incidencia sigue vigente en `dev`: SSR normaliza el valor, pero el cliente conserva un `parseInt` sin respaldo y puede solicitar `page=NaN`. La corrección ya está concentrada en una PR abierta, así que no procede cerrar ni duplicar trabajo.

## What This Changes

Normalizar de forma coherente el parámetro `page` del catálogo para que valores no numéricos conserven los resultados de la página 1 tras la hidratación.

## Best Possible Solution

Mantener un único normalizador estricto de páginas para SSR, cliente y controlador, cubrir entradas inválidas y aterrizar la corrección mediante la PR ya vinculada.
