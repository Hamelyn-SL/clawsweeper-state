## Label Justifications

- `P1`: Es un cron diario con trabajo real pendiente y el fallo puede impedir avisos de disponibilidad a usuarios en producción.
- `impact:message-loss`: El fallo afecta al envío de notificaciones de disponibilidad, dejando solicitudes pendientes sin correo en el run afectado.

## Summary

Mantendría esta issue abierta: el fallo está bien diagnosticado, sigue siendo un problema operativo real del cron y la corrección mínima no está en el código sino en la configuración de Vercel del proyecto `crons`.

## What This Changes

La issue pide corregir el fallo del cron `/api/notify-availability` cuando faltan `STOCK_KV_REST_API_URL` y `STOCK_KV_REST_API_TOKEN`.

## Best Possible Solution

Añadir las dos variables `STOCK_KV_*` al proyecto Vercel `crons` en producción, redeploy/retry del cron y dejar cualquier fallback a Mongo para una decisión de arquitectura separada.
