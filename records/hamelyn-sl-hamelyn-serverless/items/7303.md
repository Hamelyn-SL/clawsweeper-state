## Label Justifications

- `P1`: El cron diario de avisos de disponibilidad falló en producción con trabajo pendiente real, afectando un flujo automatizado de comunicación a clientes.
- `impact:message-loss`: El problema puede impedir que se envíen emails de disponibilidad esperados para solicitudes pendientes de `notify`.

## Summary

Mantener abierto: el fallo sigue siendo un incidente operativo real del cron diario y no hay evidencia de que `dev` ya haya corregido la configuración de producción de Vercel. El código actual exige `STOCK_KV_REST_API_URL` y `STOCK_KV_REST_API_TOKEN`, y el triage confirmó que faltan en el proyecto `crons` mientras hay solicitudes pendientes que no pudieron evaluarse.

## What This Changes

El reporte pide que el cron `/api/notify-availability` deje de fallar cuando faltan las variables `STOCK_KV_REST_API_URL` y `STOCK_KV_REST_API_TOKEN` en producción.

## Best Possible Solution

Configurar `STOCK_KV_REST_API_URL` y `STOCK_KV_REST_API_TOKEN` en Vercel producción para el proyecto `crons`, redeploy/retry del cron y confirmar en logs que el siguiente run procesa las solicitudes pendientes sin rechazos.

## Maintainer Decision

Required: false

## Reproduction Assessment

Sí. La ruta de reproducción está clara por código y logs: con `STOCK_KV_REST_API_URL` o `STOCK_KV_REST_API_TOKEN` ausentes, `getStocksAvailabilityFromKv` lanza antes de procesar avisos y el wrapper registra el rechazo parcial.

## Solution Assessment

Sí, la solución más estrecha es operativa: añadir las variables existentes al entorno de Vercel de `crons` y reintentar el run. Cambiar el código para caer a Mongo sería una alternativa más amplia y con impacto de carga que requiere decisión separada.
