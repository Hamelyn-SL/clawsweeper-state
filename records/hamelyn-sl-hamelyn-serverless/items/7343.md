- `P1`: La superficie expone datos sensibles mediante un secreto compartido y tiene consumidor real, pero la retirada requiere coordinación y no es un P0 inmediato de caída o pérdida de datos.
- `impact:security`: El issue trata una API paralela que devuelve datos personales/facturas y se autentica con un secreto compartido de larga vida.
- `impact:auth-provider`: La acción propuesta cambia una vía de autenticación `ATC_TOKEN` hacia APIs canónicas con Bearer/PATs y scopes.

## Summary

Mantendría este issue abierto: en `dev` todavía existe `apps/automations`, sus tres endpoints `/api/workflow/*` siguen protegidos solo por `ATC_TOKEN`, y la retirada exige coordinar antes la migración del consumidor n8n y el apagado del proyecto Vercel.

## What This Changes

Se pide eliminar `apps/automations`, limpiar sus referencias en CI/deploy/debug/docs/lockfile y retirar el proyecto Vercel `automations` después de migrar o descontinuar el flujo ATC consumidor.

## Best Possible Solution

Migrar primero el flujo ATC a `/api/v6` con PATs y scopes mínimos, cubrir cualquier capacidad que falte como la factura necesaria, y después eliminar `apps/automations` junto con sus referencias y el proyecto Vercel.
