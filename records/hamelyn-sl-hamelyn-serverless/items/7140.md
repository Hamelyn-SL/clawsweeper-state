## Summary

Keep open: current dev still has an unused `CouponBanner` with a hardcoded `5%`, and the visible `PromoStrip` still gets promo copy/coupon codes from locale JSON rather than from coupon or promotion configuration. The useful fix remains a product/data-source decision, not a safe cleanup close.

## What This Changes

The issue requests replacing hardcoded/static ecommerce promo banner copy with coupon or editable promotion configuration so visible offers cannot drift from live coupon terms.

## Best Possible Solution

Define one ecommerce promotion source of truth that binds locale, coupon code, active dates, and structured discount terms, then make `PromoStrip` use it and either reconnect or remove the legacy `CouponBanner`.

- **Keep static copy and remove legacy banner:** Remove or deprecate `CouponBanner` to eliminate the dead `5%` constant, accepting that the visible `PromoStrip` remains manually synchronized.

Unclear until maintainers choose the promotion source of truth. The narrowest maintainable fix is not just changing the `5%`; it should connect the visible strip to coupon/promotion configuration or intentionally deprecate the legacy banner.
