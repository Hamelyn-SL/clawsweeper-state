## Label Justifications

- `P3`: Es una mejora de baja urgencia sobre la fuente de promociones; no bloquea compra ni checkout, pero evita confusión futura.
- `impact:ux-friction`: Si el copy estático se desvía del cupón activo, el usuario puede ver condiciones promocionales confusas y generar soporte evitable.

## Summary

Mantener abierto: `dev` todavía conserva el `CouponBanner` heredado con `DISCOUNT = "5%"`, y la franja promocional visible sigue leyendo `promoMessage`/`promoCoupon` desde JSON de locales en vez de una fuente de promociones o cupones activa. No hay una implementación fusionada ni una PR canónica que resuelva esta divergencia; la PR BL relacionada documenta el bloque, pero no cambia comportamiento.

## What This Changes

Se pide que el copy del banner promocional de ecommerce deje de depender de texto hardcodeado y derive de la promoción/cupón activo o de una configuración editable.

## Best Possible Solution

Definir una única fuente de verdad de promociones por locale que vincule cupón, fechas y términos de descuento estructurados, hacer que `PromoStrip` la consuma, y retirar o reconectar el `CouponBanner` heredado.

## Maintainer Decision

Required: true

Kind: product_direction

Question: ¿Debe la franja promocional de ecommerce derivar el copy desde los documentos de cupón activos, desde una configuración/CMS de promociones editable, o mantenerse como copy localizado estático retirando solo el banner heredado?

Rationale: La automatización puede identificar las rutas afectadas, pero no debe decidir quién controla promociones activas, textos de marketing, locales y calendario de campañas.

Likely owner: MiguelHamelyn

Owner reason: Aparece como owner del bloque de Cupones y Promociones y la decisión afecta a comportamiento promocional, no solo a una línea de código.

Owner confidence: high

Options:

- **Fuente única de promociones (recommended):** Crear o escoger una configuración/API de promociones que referencie el cupón activo por locale y exponga texto localizado más términos estructurados para `PromoStrip`.
- **Derivar desde cupones:** Generar el mensaje desde `discount.kind` y la configuración del cupón activo, reduciendo duplicación a costa de menos control editorial del copy.
- **Mantener copy estático:** Eliminar o deprecar `CouponBanner` y aceptar que `PromoStrip` siga sincronizándose manualmente desde los locales.

## Reproduction Assessment

Parcialmente: la inspección de código reproduce la divergencia de fuente estática (`CouponBanner` con `5%` y `PromoStrip` con JSON de locales). No hay prueba en vivo de un banner visible anunciando `5%`, porque `CouponBanner` no tiene imports actuales.

## Solution Assessment

No está claro hasta que producto elija la fuente de verdad. Cambiar solo el literal `5%` sería demasiado estrecho; la solución mantenible debe conectar la franja visible a promoción/cupón/configuración o retirar explícitamente el banner heredado.
