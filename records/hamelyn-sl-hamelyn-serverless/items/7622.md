## Summary

La issue sigue siendo necesaria: `dev` solo automatiza minor/patch y rechaza cambios de major, mientras la PR de cierre continúa abierta, draft, conflictiva y pendiente de prueba operativa. Las PR por familia son ejecuciones derivadas todavía bloqueadas, no una implementación ya integrada.

## What This Changes

Se solicita automatizar actualizaciones major por familias, compartir exclusiones y evitar trabajo duplicado entre los workflows de dependencias, seguridad y Lyno.

## Best Possible Solution

Mantener un único framework con exclusiones compartidas, majors aislados en familias homogéneas, grupos de alto riesgo bajo ejecución manual y gates específicos que reproduzcan lint, typecheck, tests y build de cada superficie afectada.
