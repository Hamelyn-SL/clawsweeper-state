## Summary

La issue sigue siendo necesaria: `dev` solo automatiza minor/patch y rechaza saltos major, mientras la PR de cierre continúa abierta, en draft, conflictiva y sin prueba operativa suficiente. Las PR por familia son ejecuciones derivadas con varias incompatibilidades pendientes, no una implementación ya integrada.

## What This Changes

Se solicita automatizar las actualizaciones major en PR separadas por familias compatibles, centralizar pins y exclusiones, ampliar CI/autofix y evitar resoluciones duplicadas de alertas.

## Best Possible Solution

Integrar una única automatización coordinadora que programe solo familias homogéneas, mantenga `other` manual o subdividida, centralice pins y exclusiones, aísle credenciales y demuestre mediante `workflow_dispatch` que creación de PR, validación, production build y autofix funcionan de extremo a extremo.
