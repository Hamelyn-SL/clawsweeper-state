## Summary

Keep this open: current dev still has the reported race window in both the unified manual switch path and the packing shortcut, and the BL spec explicitly documents the atomic-claim gap as pending.

## What This Changes

Add a shared server-side atomic claim for manual carrier switches before carrier API calls, covering generic and packing-pair flows, and update the BL carrier spec.

## Best Possible Solution

Implement one shared atomic claim before any carrier API call, condition it on the current OrderSell state, release or restore it on failure, and update `BL-shipping-carrier-10` plus focused regression coverage.

## Repair Work Prompt

Fix the BL shipping carrier race in this issue. Add a shared atomic OrderSell claim before any external carrier shipment creation in both `switchCarrierForPacking` and the generic `switchCarrierManually`/`processOrderSellLabelWithCarrier` path. The claim should use a conditional `findOneAndUpdate` against `_id` plus current status/carrier/tracking/label state, block a second concurrent switch before carrier API calls, and release or restore state explicitly if shipment creation fails. Keep UI-only double-click protection as defense in depth, not the fix. Update `docs/business-logic/shipping/carrier/BL-shipping-carrier-10.md` to remove the known limitation, add or update focused regression coverage for the claim/idempotency behavior, and do not broaden unrelated carrier selection or ship-matrix behavior.
