## Label Justifications

- `P2`: La carrera puede facturar envíos duplicados, pero requiere solicitudes simultáneas sobre un mismo pedido y tiene alcance acotado.
- `impact:other`: El impacto concreto son envíos externos duplicados y costes operativos, fuera de las clases específicas disponibles.

## Summary

La incidencia sigue siendo necesaria: `dev` mantiene una ventana de carrera entre la comprobación en memoria y la creación externa de etiquetas, y la propia especificación la documenta como limitación pendiente.

## What This Changes

Añadir un reclamo atómico compartido al cambio manual de transportista para impedir que solicitudes simultáneas creen envíos duplicados facturables.

## Best Possible Solution

Introducir un claim condicional compartido antes de cualquier API de carrier, con liberación controlada ante error, recuperación de claims obsoletos y cobertura de packing y flujo genérico.

## Maintainer Decision

Required: true

Kind: product_direction

Question: ¿Qué semántica de recuperación debe tener el claim persistente cuando el proceso falla o termina después de crear el envío externo?

Rationale: La exclusión mutua es necesaria, pero el tiempo de expiración y la recuperación determinan si se bloquean reintentos válidos o se reabren duplicados.

Likely owner: JavierHamelyn

Owner reason: Concentró la introducción y el endurecimiento previo de las rutas de cambio manual afectadas.

Owner confidence: high

Options:

- **Claim con propietario y expiración (recommended):** Persistir un token y fecha de claim, rechazar competidores y permitir recuperación auditada tras una caducidad definida.
- **Claim sin recuperación automática:** Mantener el pedido bloqueado hasta una intervención operativa explícita tras una caída.
- **Delegar idempotencia al carrier:** Usar una clave idempotente del carrier cuando todos los proveedores implicados la soporten de forma uniforme.

## Reproduction Assessment

Sí, desde código: dos solicitudes concurrentes pueden superar la lectura y el guard antes de que exista una escritura excluyente. No se ejecutó una carrera contra un carrier real.

## Solution Assessment

Sí, un claim compartido es la vía más mantenible, siempre que defina recuperación ante fallos y no use solo el carrier destino como bloqueo.
