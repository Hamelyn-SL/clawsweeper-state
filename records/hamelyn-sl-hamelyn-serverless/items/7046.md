## Label Justifications

- `P2`: La carrera puede emitir envíos facturables duplicados, aunque requiere solicitudes simultáneas sobre un mismo pedido.
- `impact:other`: El impacto concreto combina costes externos, etiquetas huérfanas y seguimiento inconsistente.

## Summary

La carrera sigue presente en `dev`: ambos caminos comprueban el estado en memoria y después preparan el pedido con un filtro limitado a `_id`, antes de llamar al carrier. La issue sigue siendo necesaria.

## What This Changes

Añadir un reclamo atómico y recuperable al cambio de transportista para impedir la creación concurrente de envíos duplicados.

## Best Possible Solution

Crear una mutación de repositorio que reclame condicionalmente el pedido antes de cualquier API externa, usarla desde ambos flujos y restaurar un estado reintentable cuando falle la creación.
