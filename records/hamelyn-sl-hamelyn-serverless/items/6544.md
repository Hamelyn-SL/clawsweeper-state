## Label Justifications

- `P2`: La automatización de releases es una mejora operativa importante y acotada, pero no hay una emergencia activa ni un runtime de usuario inutilizable.

## Summary

Este PR sigue siendo necesario porque `dev` aún no tiene el despliegue EAS automatizado, pero el head no está listo para merge: conserva los cinco hallazgos de los ciclos anteriores, tiene conflictos con la rama base y no aporta prueba real del flujo beta. La dirección operativa ya está acordada en la issue de release, por lo que corresponde actualizar y validar este candidato, no cerrarlo ni abrir una implementación paralela.

## What This Changes

El PR añade un workflow manual de GitHub Actions para hacer build y submit de Supply mediante EAS, con selectores de plataforma, lane y bump, junto con el script de versionado, perfiles de submit y documentación.

## Best Possible Solution

Mantener un workflow que solo opere desde una rama de release, sincronice las cinco fuentes de versión mediante el flujo Expo soportado sin editar manualmente carpetas generadas, use una versión fijada de EAS CLI, publique primero ambos binarios y permita mergear el bump en `dev` únicamente tras comprobar que la versión está disponible en las stores.
