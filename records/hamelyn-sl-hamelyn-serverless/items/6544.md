## Summary

Este PR sigue siendo necesario porque `dev` aún no automatiza el despliegue EAS, pero el head actual no está listo para merge: continúa en borrador, tiene conflictos, carece de prueba real y mantiene defectos bloqueantes en la secuencia de publicación, el versionado y la seguridad de la automatización.

## What This Changes

El PR añade un workflow manual de EAS Build + Submit para Supply, perfiles beta/release, un script de incremento de versión y documentación del proceso de despliegue.

## Best Possible Solution

Mantener un historial limpio y hacer el release desde una rama dedicada: sincronizar las cinco fuentes mediante el flujo Expo admitido, construir y enviar primero a beta, confirmar el binario en ambas stores y promover después la versión a `dev` mediante un PR revisable.
