## Label Justifications

- `P0`: El PR corrige una exposición pública de costes, proveedor, métricas e inventario interno en ecommerce.
- `merge-risk: 🚨 compatibility`: La disponibilidad pública deja de exponer `units` y eso cambia consumidores existentes del flujo de carrito/checkout.
- `merge-risk: 🚨 security-boundary`: El cambio define qué campos internos cruzan la frontera pública de HTML/RSC y APIs JSON.

## Summary

Mantener abierto: el PR aborda la fuga P0 con una allowlist pública amplia, pero el último arreglo de stock aún no recibe `units` desde el flujo de checkout, así que la validación de sobreventa sigue degradada. Además falta prueba runtime suficiente después de los últimos commits para una frontera pública de datos sensibles.

## What This Changes

El PR añade serializers públicos para producto, disponibilidad, búsqueda, featured y carrito, centraliza campos internos de producto y ajusta la validación de disponibilidad del checkout.

## Best Possible Solution

Aterrizar el serializer público, pero antes de mergear asegurar la validación server-side con `units` reales del carrito y aportar una prueba de staging que demuestre cero campos sensibles en PDP/RSC y endpoints JSON.

## Reproduction Assessment

Sí: por inspección de fuente en el head del PR, `CartContext.checkAvailability` envía productos sin `units` y `classifyCartAvailability` cae a `1`, así que una cantidad mayor del carrito no se compara contra stock real. No he ejecutado el flujo contra staging.

## Solution Assessment

No del todo: la allowlist pública es la dirección mantenible, pero la reparación de sobreventa debe llevar la cantidad real hasta la validación server-side o validarla al modificar el carrito.
