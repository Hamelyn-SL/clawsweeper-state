## Summary

Este PR sigue siendo necesario para cerrar una filtración P0 de datos internos, pero no debería mergearse todavía: el head actual sanea mejor los payloads públicos y atiende parte del feedback previo, aunque deja roto el límite de unidades del carrito al ocultar `units` sin adaptar el cliente que todavía lo usa.

## What This Changes

El PR añade serialización pública allowlist/denylist para productos, disponibilidad, autocompletado, featured y carrito, y ajusta el checkout para validar cantidades contra stock server-side.

## Best Possible Solution

Mantener el saneamiento fail-closed de datos internos, pero adaptar el flujo de carrito a un contrato público compatible que valide cantidades sin exponer stock exacto, con prueba real de staging en las rutas públicas afectadas.

## Solution Assessment

No del todo: el serializer público y el backstop server-side van en buena dirección, pero la solución debe actualizar también el contrato usado por el carrito para no depender de un campo que el PR elimina del payload público.
