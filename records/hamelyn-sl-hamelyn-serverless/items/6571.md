## Summary

La issue sigue siendo necesaria: el `dev` actual no define `SKYPOD`, la Estación no crea ni cierra una sesión de productividad propia y una ruta de transición continúa buscando una sesión `PICKING`. No hay una PR abierta que cubra el trabajo; antes de implementarlo conviene confirmar qué acciones excepcionales deben incrementar el contador.

## What This Changes

Añadir `SKYPOD` como nuevo tipo de productividad para la Estación Skypod de Admin, con sesión, persistencia y conteo de productos confirmados.

## Best Possible Solution

Incorporar `SKYPOD` de extremo a extremo reutilizando el patrón de `AUTO_PACKING`: enum compartido, configuración, sanitizado y cálculo de metadata, sesión ligada a `currentMode === "preparation"`, actualización solo tras confirmaciones válidas y cierre al abandonar el modo, con cobertura dirigida de los eventos que suman.
