## Summary

Este PR sigue siendo necesario para la incidencia abierta de cache remoto, pero no está listo para merge: la exclusión de `one-time-scripts` puede restaurar un `dist` obsoleto de `apps/local`, y la única prueba publicada declara explícitamente que está bloqueada en lugar de mostrar un resultado post-cambio.

## What This Changes

El PR ajusta las claves de caché de `build` de Turborepo, añade configuraciones por paquete o app y separa la compilación de producción de `@hamelyn/core` para obtener aciertos de remote cache en Vercel.

## Best Possible Solution

Mantener todos los archivos que `apps/local` emite dentro de los inputs de `local#build` —o excluirlos también del `tsconfig` mediante una decisión explícita— y adjuntar una ejecución real y redactada de Vercel/Turborepo que confirme un acierto remoto sin reutilizar artefactos incorrectos.

## Reproduction Assessment

Sí, por inspección de código: cambiar un archivo bajo `apps/local/one-time-scripts`, ejecutar `local#build` dos veces con caché y comprobar `dist` expone el problema, porque el `tsconfig` lo incluye aunque el PR lo elimina del hash.

## Solution Assessment

No. La optimización de `local#build` no es segura mientras esos scripts sigan incluidos en la compilación; retirar la negación es la corrección más estrecha y mantiene el contrato actual de salida.
