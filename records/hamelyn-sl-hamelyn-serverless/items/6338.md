- `P1`: The issue reports recurring production marketplace-crons create failures that leave MercadoLibre SKUs in upload error until recovery handles them.
- `impact:other`: The concrete impact is marketplace catalog sync/recovery failure for affected SKUs, which is meaningful but outside the owned security/session/message/auth impact classes.

## Summary

Keep this issue open: the merged fix covers MercadoLibre `internal_error`/5xx recovery, but the reopened `shipping.default.error` variant is still not covered by the current classifier or recovery regex.

## What This Changes

MercadoLibre create shipping-provider errors should be classified and recovered as transient so affected SKUs are retried instead of staying in marketplace sync error.

## Best Possible Solution

Extend the MercadoLibre retry classifier and create recovery regex for the specific `shipping.default.error` shipping-provider signature, add regression coverage, and keep existing permanent validation/image/language handling intact.

## Solution Assessment
