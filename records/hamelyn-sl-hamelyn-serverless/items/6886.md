## Summary

La issue sigue siendo necesaria: en `dev` todavía aparecen los patrones reportados de DOM inválido y el comentario de triage ya acota que el arreglo completo es un barrido grande, no una limpieza ya absorbida por el PR de Next 16.

## What This Changes

La issue pide barrer el monorepo para corregir HTML inválido que React 19 detecta como nesting de DOM y warnings relacionados de MUI Tabs.

## Best Possible Solution

Mantener la issue abierta y resolverla como barrido frontend coordinado por patrones: sacar controles de `DialogContentText`, reemplazar wrappers de `Typography` para children arbitrarios, evitar forms anidados y normalizar el estado de Tabs antes de validar en navegador.
