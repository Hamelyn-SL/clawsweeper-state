## Summary

La PR sigue siendo necesaria porque `dev` aún calcula la caché de `lint` únicamente con `$TURBO_DEFAULT$`. El parche es acotado, conserva las invalidaciones de código y configuración, y no excluye archivos JS/TS versionados que los linters actuales procesen; no se encontraron defectos concretos.

## What This Changes

La PR modifica `turbo.json` para que la caché de `lint` ignore Markdown, activos estáticos y árboles nativos generados que ESLint no procesa.

## Best Possible Solution

Integrar estas exclusiones acotadas cuando el head exacto complete la revisión humana y los gates normales, manteniendo `$TURBO_DEFAULT$` y la invalidación transitiva de `@hamelyn/code-config`.

Sí. `dev` conserva `$TURBO_DEFAULT$` como único input y la PR aporta una ruta concreta mediante `turbo run lint --dry=json` y mutaciones controladas de archivos.

## Solution Assessment

Sí. Cambiar únicamente `lint.inputs` es la solución más estrecha, y las rutas y extensiones excluidas no pertenecen al alcance actual de ESLint; conservar `$TURBO_DEFAULT$` evita sustituir la fuente de verdad de Turbo.
