## Label Justifications

- `P0`: La PR aborda un fallo activo que hace desaparecer visualmente productos y produce altas inconsistentes en el flujo principal de captación de Supply.
- `merge-risk: 🚨 session-state`: La implementación puede sobrescribir el contador y el importe compartidos con una respuesta anterior cuando dos altas terminan fuera de orden.

## Summary

Mantener abierta: el enfoque aborda la causa original, pero el último commit permite que una respuesta antigua vuelva a publicar un contador y un importe anteriores después de una alta más reciente. La PR tampoco aporta todavía una ejecución real del carrito autenticado con `429` controlado y doble pulsación, por lo que no está lista para merge.

## What This Changes

La PR conserva el último estado válido del carrito ante errores de lectura, elimina refrescos autorrealimentados y serializa las solicitudes de añadir productos en Supply.

## Best Possible Solution

Mantener una secuencia autoritativa para las altas del carrito —también entre cambios de producto— o reconciliar las respuestas mediante generación/versionado o una lectura final autoritativa, sin permitir que una instantánea antigua reduzca el estado compartido; después validar el flujo completo en un entorno autenticado.

No se ejecutó una reproducción interactiva durante esta revisión de solo lectura.

## Solution Assessment

No todavía. Conservar el último estado válido, eliminar el efecto autorrealimentado y serializar las altas es el enfoque adecuado, pero la sincronización debe impedir que una respuesta obsoleta sobrescriba otra más reciente y necesita prueba real antes del merge.
