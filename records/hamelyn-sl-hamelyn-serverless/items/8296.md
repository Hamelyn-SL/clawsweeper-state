## Label Justifications

- `P1`: La condición descarta de forma continuada las métricas de una estación simultánea durante una operación activa.
- `impact:data-loss`: Las confirmaciones de la estación sin sesión se descartan sin contabilizar, perdiendo datos de productividad.

## Summary

La incidencia sigue siendo necesaria: `START` de SKYPOD recupera una sesión solo por operario y operación, mientras el contador exige estación; la segunda estación queda sin sesión y sus confirmaciones no se suman.

## What This Changes

Corregir la productividad Skypod para que cada combinación de operario, día y estación tenga su propia sesión activa.

## Best Possible Solution

Añadir una consulta específica para SKYPOD por operario, operación, estación y día, usarla en START/UPDATE/END y conservar las consultas actuales para las demás operaciones.

## Maintainer Decision

Required: false

## Reproduction Assessment

Sí, desde código: dos START de SKYPOD el mismo día con el mismo usuario y estaciones distintas devuelven la primera sesión antes de crear la segunda.

## Solution Assessment

Sí, si la clave por estación se incorpora de forma uniforme al inicio, actualización y cierre de SKYPOD sin alterar las demás operaciones.
