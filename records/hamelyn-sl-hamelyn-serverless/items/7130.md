## Summary

Keep open: current dev still has the live ProductPageB/ProductPageC reference-price helpers returning no strikethrough price when `priceNew` and `groupOriginalPrice` are absent or too low, while the `×1.37` fallback only exists on the prescriptor price section and no PR currently owns this bug.

## What This Changes

The issue asks for the live ecommerce product page to use the cheapest visible price `×1.37` as the reference-price fallback when the new price is unknown.

## Best Possible Solution

Add a shared reference-price helper that prefers known new/original prices and falls back to `getMinUsedPrice(visibleAvailability) * 1.37` in both live variants, with the Product Page BL spec/test updated in the same coordinated PR.
