## Summary

La issue sigue siendo necesaria: `dev` continúa insertando cualquier sustituto en la op S original sin distinguir drawers BIN. El PR candidato https://github.com/Hamelyn-SL/hamelyn-serverless/pull/7506 aún está abierto y tiene observaciones concretas sobre sincronización de `OrderSell` y consistencia entre stock, MongoDB y Exotec, por lo que la issue debe permanecer abierta hasta que ese arreglo se corrija y se fusione.

## What This Changes

La issue solicita derivar los sustitutos interactivos ubicados en drawers BIN a una op `S-EX` con preparation request de Exotec, manteniendo en la op original los sustitutos de estantería.

## Best Possible Solution

Consolidar el arreglo en https://github.com/Hamelyn-SL/hamelyn-serverless/pull/7506 reutilizando el patrón batch completo: clasificar BIN, reservar el stock, persistir una op `S-EX`, sincronizar `OrderSell`, enviar la preparation request con una estrategia explícita de recuperación ante fallos y documentar el flujo en `skills/hamelyn-knowledge/fulfillment/01-picking-v3.md`.

El PR actual necesita completar la sincronización de `OrderSell` y definir un orden o compensación segura para reserva, persistencia y llamada a Exotec antes de considerarse la mejor implementación.
