- `impact:ux-friction`: El operario puede continuar, pero el lote no encontrado obliga a salir de la pantalla principal y usar otra vista para localizarlo por EAN/Pedido de Compra.

## Summary

Mantener abierta: `dev` todavía no integra el buscador por EAN/Pedido de Compra dentro del modal de revisión. La entrada manual de tracking ya existe, pero cuando no hay coincidencia el flujo actual solo avisa y obliga a usar la pantalla separada de buscador EAN.

## What This Changes

La issue pide añadir entrada manual de lote y un fallback integrado por EAN/Pedido de Compra en la pantalla principal de revisión.

## Best Possible Solution

Integrar en `OrderReviewModal` un fallback compacto que reutilice la lógica de `useEanFinderSearch`/`ean-finder`, aparezca solo cuando el tracking no resuelva y permita abrir la orden sin abandonar el flujo de revisión.
