## Summary

El PR aborda un problema real de coste y observabilidad, pero el `HEAD` todavía puede perder lotes de telemetría, altera una ruta con secretos mediante una instalación no reproducible y no aporta prueba extrema a extrema contra BigQuery.

## What This Changes

El PR añade un writer de eventos BL hacia BigQuery, lo conecta parcialmente a ecommerce y crons, y suma un guardián de instrumentación, un agregado diario y una alerta de volumen.

## Best Possible Solution

Conservar los envíos por scope hasta poder esperarlos o registrarlos con `waitUntil`, fijar la dependencia del workflow y validar una inserción redactada contra BigQuery antes de activar el flag; decidir además si el sink debe usar Storage Write API.
