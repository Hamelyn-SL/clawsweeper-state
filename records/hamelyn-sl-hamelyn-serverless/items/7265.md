## Summary

Mantener abierta: la migración a BigQuery no está en `dev`; la telemetría `blmetrics` y el grafo BL siguen en la PR abierta https://github.com/Hamelyn-SL/hamelyn-serverless/pull/7116, y esta issue representa el siguiente paso arquitectónico cuando esa base exista.

## What This Changes

Migrar la telemetría de invocaciones BL desde la colección temporal `blmetrics` en Mongo a BigQuery, manteniendo el contrato `{count, lastLogAt}` del grafo de Data Dashboards.

## Best Possible Solution

Aterrizar primero la base de telemetría BL, elegir una vía de ingesta BigQuery alineada con Data Platform, modelar una tabla/vista typed para series temporales por BL-ID y hacer que el grafo lea esa fuente antes de retirar `blmetrics`.

Options:

- **Usar Log Drain y modelado BigQuery (recommended):** Aprovecha `hamelyn-vercel-logs` como transporte existente y añade parsing/staging/mart versionados para BL antes de conectar el grafo.
- **Streaming directo desde el sink:** Reduce parsing de logs pero mete BigQuery en el path runtime y requiere una política explícita de fallos/reintentos.
- **Exportar desde Mongo como puente:** Permite migrar después de `blmetrics`, pero mantiene temporalmente escritura operacional y no resuelve la granularidad de eventos si solo existen agregados.

## Reproduction Assessment

No aplica como reproducción de bug: es una migración de destino analítico. La comprobación de código sí confirma que la implementación de BigQuery para BL no está en `dev`.

## Solution Assessment

Aún no está decidido. La dirección más mantenible parece reutilizar el log drain y materializar una vista/tabla typed en BigQuery, pero debe esperarse a que la PR base de telemetría BL quede estable o mergeada.
