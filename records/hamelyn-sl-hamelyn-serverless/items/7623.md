## Label Justifications

- `P0`: El fallo afecta al flujo principal de captación de Supply y hace desaparecer o fallar altas de productos durante sesiones reales.
- `impact:data-loss`: El cliente puede sustituir un carrito válido por estado vacío y ocultar productos que siguen persistidos, induciendo nuevas altas inconsistentes.

## Summary

Mantener abierta: el fallo sigue presente en `dev` y la PR vinculada que lo corrige continúa abierta y pendiente de prueba real en un carrito autenticado.

## What This Changes

Se solicita impedir que los productos añadidos al monedero de Supply desaparezcan, se acumulen tarde o se registren de forma inconsistente.

## Best Possible Solution

El flujo final debe conservar el último carrito válido ante fallos transitorios, refrescar solo por cambios de autenticación, serializar las altas y navegar únicamente después de que el servidor confirme un carrito actualizado; la PR vinculada debería fusionarse tras demostrar esos casos en un entorno autenticado.

Required: false

## Solution Assessment

La dirección de https://github.com/Hamelyn-SL/hamelyn-serverless/pull/7636 es la solución más estrecha para las causas observadas, pero aún no puede considerarse completa sin prueba real del `429`, la conservación del estado y la serialización de altas.
