## Summary

Debe seguir abierta: en `dev` los workflows TS candidatos siguen haciendo `pnpm install --frozen-lockfile` del monorepo y `pnpm --filter @hamelyn/core build`, así que la optimización pedida aún no está implementada. La issue está asignada a `danielmenchen-hamelyn` y el alcance toca crons productivos, por lo que conviene que Infra confirme el piloto y la validación antes de cambiar todos los workflows.

## What This Changes

La issue pide reducir coste de GitHub Actions en crons TS eliminando el build de `@hamelyn/core`, usando install filtrado con `--filter local...` y verificando que los scripts no dependen de `dist`.

## Best Possible Solution

Hacer un piloto acotado en los workflows TS de mayor coste, cambiar solo los pasos de setup necesarios, y medir runs reales antes/después con una verificación explícita de dependencias e imports.
