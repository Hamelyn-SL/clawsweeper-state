## Label Justifications

- `P2`: La vulnerabilidad high es alcanzable desde rutas autenticadas de producción, pero no hay evidencia de explotación activa ni de indisponibilidad general.
- `impact:security`: Un fichero XLSX manipulado puede agotar recursos del proceso mediante una dependencia runtime vulnerable.

## Summary

Debe seguir abierta: `dev` mantiene `xlsx@0.18.5` y varias rutas de producción entregan ficheros externos a `XLSX.read()`, sin un PR abierto que implemente la actualización.

## What This Changes

Actualizar las dependencias directas de `xlsx` en Admin y Core para eliminar el ReDoS al procesar archivos XLSX.

## Best Possible Solution

Resolver las dos alertas mediante un único PR que fije el tarball oficial e inmutable de `xlsx@0.20.3` en Admin y Core, regenere el lockfile y aporte pruebas reales de lectura y escritura sobre los flujos XLSX críticos.
