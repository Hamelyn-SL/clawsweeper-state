## Label Justifications

- `P0`: The issue describes unauthenticated access to customer PII through predictable public Blob URLs, which is a security-boundary failure.
- `impact:security`: The reported behavior exposes customer names, addresses, and phone numbers from admin PDFs/ZIPs without authentication when a Blob pathname is guessed.

## Summary

Keep this issue open: current `dev` still has public, deterministic admin Blob paths on the reported code paths, and the linked mitigation PR is open but currently conflicting rather than merged.

## What This Changes

The issue asks to stop exposing admin PDFs/ZIPs containing customer PII through public Vercel Blob URLs with predictable pathnames.

## Best Possible Solution

Land a narrow mitigation for random, non-enumerable admin Blob paths now, then keep the private Blob/authenticated-read hardening as a separate follow-up if direct public URLs remain unacceptable.

## Solution Assessment

Yes for the immediate mitigation path: randomizing pathnames on the reported public uploads is a narrow maintainable fix. The durable authenticated-read/private-store solution is broader, and current `dev` has not completed either mitigation for these admin exports.
