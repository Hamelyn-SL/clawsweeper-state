- `P2`: Corrige cancelaciones erróneas de pedidos reales, pero el alcance conocido es limitado y requiere revisión normal, no una intervención de emergencia.
- `merge-risk: 🚨 compatibility`: El nuevo estado deja de ser cancelable para el cliente y añade un valor persistido que deben entender todos los consumidores del ciclo de vida.
- `merge-risk: 🚨 message-delivery`: El cron puede registrar `reminderSentAt` antes de saber si Slack entregó el aviso, suprimiendo futuros recordatorios tras un fallo.
- `merge-risk: 🚨 other`: La autocancelación puede desalinear el pedido local, el pedido del proveedor y los efectos financieros sin una reconciliación fiable.

## Summary

El PR sigue siendo necesario porque `dev` todavía conserva el fallo original, pero no está listo para merge: mantiene un bloqueo previo de cancelación, introduce una autocancelación insegura para resultados aún ambiguos, tiene defectos operativos adicionales y carece de prueba real satisfactoria.

## What This Changes

El PR añade un estado persistido para confirmaciones dropshipping no concluyentes, reintento administrativo, avisos operativos, autocancelación a las 48 horas, representación en ecommerce/admin y documentación asociada.

## Best Possible Solution

Mantener los resultados ambiguos pendientes hasta una reconciliación o rechazo explícito, permitir una cancelación atómica que abra la reconciliación necesaria con el proveedor y demostrar en staging el ciclo completo antes del merge.
