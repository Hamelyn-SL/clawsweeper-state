## Label Justifications

- `P1`: La firma puede dejar precio o cantidad temporalmente desincronizados para varios SKU de un marketplace activo.
- `impact:other`: El impacto concreto es una sincronización parcial de inventario y precios de eBay, fuera de las categorías específicas disponibles.

## Summary

La issue puede cerrarse porque `dev` ya trata los 5xx de eBay como transitorios, reintenta la operación, conserva los SKU pendientes para ejecuciones posteriores y propaga el fallo parcial al resumen del cron; la discusión canónica previa además confirmó que esta firma correspondía a una caída externa de eBay.

## What This Changes

La issue solicita clasificar y reintentar los errores 500 de eBay durante `bulk_update_price_quantity`, manteniendo una señal agregada de los SKU no sincronizados.

## Best Possible Solution

Mantener la clasificación, los reintentos y la observabilidad actuales, y abrir una nueva incidencia únicamente si evidencia posterior demuestra que un 5xx no se reintenta o que los SKU dejan de quedar pendientes para el siguiente cron.

## Reproduction Assessment

No existe una reproducción viva determinista porque exige que la API externa de eBay devuelva un 500, pero el recorrido de esa respuesta por el código actual es reproducible con alta confianza: se clasifica como transitoria, se reintenta y termina en la señal parcial agregada si vuelve a fallar.

## Solution Assessment

Sí. La implementación actual es la vía más estrecha y mantenible: reintento acotado inmediato, conservación para el siguiente cron y separación entre fallos transitorios y permanentes sin convertir una caída externa en error terminal por SKU.
