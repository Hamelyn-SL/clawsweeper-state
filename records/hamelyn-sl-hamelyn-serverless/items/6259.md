## Summary

La issue puede cerrarse: `dev` ya clasifica los HTTP 500 de eBay como transitorios, reintenta el lote o los SKU afectados, conserva los fallos transitorios para el siguiente ciclo y publica un resumen agregado; la indisponibilidad remota también quedó recogida en la incidencia canónica ya cerrada.

## What This Changes

La issue solicita tratar los HTTP 500 de eBay en `bulk_update_price_quantity` como fallos transitorios con retry/backoff y señal agregada de los SKU no sincronizados.

## Best Possible Solution

Conservar la política actual y abrir una nueva incidencia únicamente si logs recientes demuestran que el retry no se ejecuta, que los SKU pierden `needsUpdatePrice` o que el resumen deja de reflejar fallos parciales.

## Reproduction Assessment

Sí, a nivel de fuente y evidencia histórica de producción: un HTTP 500 entra en la clasificación transitoria, activa el retry y, si persiste, produce un fallo parcial sin convertir el SKU en error permanente. No se ha provocado una nueva caída real de eBay.

## Solution Assessment

Sí. La implementación actual es la solución más estrecha y mantenible: distingue fallos transitorios de permanentes, limita el retry inmediato y conserva el estado por SKU para el siguiente ciclo.
