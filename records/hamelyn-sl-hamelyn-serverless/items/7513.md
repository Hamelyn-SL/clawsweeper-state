## Label Justifications

- `impact:security`: El flujo propuesto ejecutaría código de ramas de PR y posteriormente usaría permisos de escritura sobre ramas y metadatos de GitHub.

## Summary

Debe seguir abierta: `dev` no implementa el resolver solicitado, el único PR relacionado se cerró sin merge al descartarse su ubicación y la arquitectura actual solo aporta primitivas reutilizables, no el comportamiento completo.

## What This Changes

La issue solicita un subsistema cloud en `apps/agents` que detecte conflictos de PRs contra `dev`, resuelva únicamente los inequívocos, valide el resultado y derive los demás a revisión humana.

## Best Possible Solution

Implementar un poller GraphQL dedicado con ledger `(PR, base SHA, head SHA)`, ejecutar el análisis y la validación sin secretos de escritura en un sandbox efímero y reservar commit, push, comentarios y labels a un controlador transaccional que vuelva a verificar todo el estado.
