## Label Justifications

- `P1`: Un cambio global de estado HTTP puede alterar de inmediato reintentos y alertas de flujos cron activos.
- `merge-risk: 🚨 compatibility`: El helper sustituye el éxito HTTP histórico por 500 para todos los fallos completos sin una política por ruta.
- `merge-risk: 🚨 availability`: Los consumidores pueden interpretar el nuevo 500 como fallo del cron y activar reintentos o alertas adicionales.

## Summary

La propuesta mejora la observabilidad, pero introduce una política HTTP global no decidida para todos los crons; necesita decisión de producto antes de fusionarse.

## What This Changes

La rama añade `summarizeCronRun`, registra `[cron-summary]` estructurado y devuelve HTTP 500 cuando todas las tareas de un cron compartido fallan.

## Best Possible Solution

Separar el resumen estructurado compatible de una política explícita de severidad por ruta o cron, con una migración y pruebas de los consumidores que deban adoptar HTTP 500.
