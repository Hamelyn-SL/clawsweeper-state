## Label Justifications

- `P1`: El agotamiento recurrente del runtime retrasa el procesamiento de notificaciones Amazon de un cron operativo.
- `impact:crash-loop`: La incidencia documenta terminaciones 504 al alcanzar el límite de ejecución del proceso.

## Summary

Mantener abierta: `dev` reserva margen antes de recibir otro batch, pero sigue procesando todos los mensajes ya recibidos sin comprobar el presupuesto entre ellos; una secuencia lenta puede alcanzar los 150 segundos antes del borrado SQS.

## What This Changes

La incidencia solicita impedir que `/api/amazon-notifications-pull` agote el runtime de 150 segundos mientras procesa un batch SQS de notificaciones Amazon.

## Best Possible Solution

Añadir un guard de presupuesto antes de cada mensaje, reservar tiempo para el borrado batch y dejar en SQS los mensajes no iniciados con `retainedReason: "execution_budget"` y telemetría observable.
