## Label Justifications

- `P1`: El timeout terminal afecta repetidamente a un cron de producción que procesa cambios de pedidos y puede dejar trabajo pendiente hasta ejecuciones posteriores.
- `impact:crash-loop`: La señal documentada son ejecuciones recurrentes que agotan el runtime de Vercel y terminan en 504.

## Summary

Mantener abierta: `dev` sigue protegiendo únicamente el inicio de cada batch, no el procesamiento de cada mensaje, y la única PR que cubría ese hueco se cerró sin fusionar. Las incidencias relacionadas de Mongo, `getOrder` y stock inexistente tienen causas distintas, por lo que no sustituyen este seguimiento.

## What This Changes

Evitar que `/api/amazon-notifications-pull` agote los 150 segundos procesando varios mensajes lentos de un mismo batch SQS, reteniendo para el siguiente run los mensajes que no puedan iniciarse con margen suficiente.

## Best Possible Solution

Aplicar un guard antes de cada mensaje que reserve margen para procesarlo y ejecutar `DeleteMessageBatch`, dejar sin borrar los mensajes no iniciados y acotar, cuando sea viable, las operaciones externas al tiempo restante para que ninguna llamada individual alcance el timeout de plataforma.

## Repair Work Prompt

Corrige el agotamiento de `/api/amazon-notifications-pull` durante el procesamiento de un batch SQS. Parte del `dev` actual y usa https://github.com/Hamelyn-SL/hamelyn-serverless/pull/5799 únicamente como referencia. En `apps/crons/src/controller/amazon-notifications-pull/index.ts`, comprueba `executionBudgetMs` antes de iniciar cada mensaje, reserva margen para completar el mensaje y ejecutar `DeleteMessageBatch`, registra y devuelve los mensajes restantes como `deferred` con `retainedReason: "execution_budget"`, y déjalos sin borrar para el siguiente run. Conserva el borrado batch de los mensajes ya completados. No cambies la lógica funcional de `getOrder`, stock inexistente, deduplicación, locks, visibilidad SQS, inicialización Mongo ni los parámetros públicos de la ruta. Si una operación individual puede superar el presupuesto restante, añade un timeout acotado solo si puede hacerse sin ampliar el contrato; en caso contrario documenta ese límite en la PR. No edites `CHANGELOG.md` ni añadas scripts one-time. Ejecuta lint y build de `crons` y aporta prueba real redactada que muestre el corte anticipado, el borrado de completados, la retención de no iniciados y la ausencia de 504.
