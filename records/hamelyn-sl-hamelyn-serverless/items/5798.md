## Summary

Keep open: current `dev` still only checks the execution budget before receiving the next SQS batch, while the reported failure is about running out of the 150s Vercel budget while processing messages inside a batch. The linked fix candidate was closed unmerged, and the issue was later marked confirmed live.

## What This Changes

Add per-message execution-budget handling to `/api/amazon-notifications-pull` so processed messages can be deleted and unstarted messages deferred before the Vercel 150s timeout.

## Best Possible Solution

Land a narrow cron-controller fix that checks budget before each message, defers unstarted SQS messages with an observable `execution_budget` reason, deletes completed messages before returning, and confirms the 150s timeout signature disappears after deploy.
