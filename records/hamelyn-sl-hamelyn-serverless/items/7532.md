## Label Justifications

- `P2`: Es una feature interna planificable y desactivada por defecto, pero necesita correcciones y una decisión de seguridad antes del merge.
- `merge-risk: 🚨 security-boundary`: El worker ejecuta contenido de ramas de PR mientras dispone de credenciales operativas y capacidad de escritura.
- `merge-risk: 🚨 automation`: La idempotencia y validación actuales pueden omitir reintentos, saltarse el typecheck o dejar el trigger fallando tras el despliegue.

## Summary

Este PR sigue siendo necesario porque `dev` aún no incorpora la capacidad solicitada, pero el head actual no es apto para merge: expone credenciales operativas a código controlado por ramas de PR, bloquea nuevos intentos cuando cambia el head y puede omitir el typecheck antes de hacer push.

## What This Changes

El PR añade un workflow, un endpoint M2M, un schedule y un runner en Vercel Sandbox que detectan conflictos contra `dev`, intentan resolverlos con Codex y pueden empujar el merge resultante a la rama del PR.

## Best Possible Solution

Separar un worker sin secretos que produzca una resolución verificable de un controlador confiable que valide y haga el push; usar `(PR, dev SHA, head SHA)` como identidad del intento, ejecutar todos los checks disponibles y pilotar primero con ramas internas permitidas.
