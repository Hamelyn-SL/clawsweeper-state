## Summary

Conviene mantener esta PR abierta: la funcionalidad aún no existe en `dev` y el candidato conserva trabajo útil, pero el head actual no es mergeable desde el punto de vista de revisión porque procesa contenido controlado por las ramas de PR con credenciales sensibles, mantiene tres blockers del ciclo anterior y carece de prueba positiva del runtime actual.

## What This Changes

Añade un agente cloud en `apps/agents` y un workflow por push a `dev` para detectar, validar y resolver automáticamente conflictos mecánicos en ramas de pull requests.

## Best Possible Solution

Usar una arquitectura de dos fases: analizar y producir un parche en un entorno sin credenciales ni scripts de la PR, verificar repositorio, modos Git, SHAs y rutas permitidas, y aplicar el parche desde un controlador confiable con un token mínimo y de corta duración; mantener el modo mutante desactivado hasta demostrar el camino de éxito del head final.
