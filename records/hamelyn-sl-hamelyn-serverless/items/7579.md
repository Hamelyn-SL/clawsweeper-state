## Summary

Conviene mantener este issue abierto: `dev` sigue construyendo los campos personalizados de eDesk a partir de un solo `OrderSell`, aunque el cuerpo del ticket enumera todos los envíos; la captura aportada coincide exactamente con esa asimetría.

## What This Changes

El reporte solicita que eDesk permita acceder desde sus campos personalizados a todas las partes de un pedido ecommerce mixto, incluidas las expediciones de libros nuevos y de segunda mano.

## Best Possible Solution

Mantener la URL directa actual para pedidos de una sola expedición y, cuando haya varias, usar el campo existente `Hamelyn · Admin URL` para abrir el listado de `OrderSell` filtrado por el `orderId` del ecommerce, mostrando todas las partes sin ampliar el esquema manual de eDesk.

Sí, a nivel de fuente con alta confianza: basta un checkout cuyo `codeIdentifier` tenga más de un `OrderSell`; el endpoint carga todos, pero genera los campos personalizados desde `orderSells[0]`. No se realizó una creación real de ticket contra eDesk durante esta revisión de solo lectura.

## Solution Assessment

Sí: reutilizar el único campo de URL para abrir una vista de Admin filtrada por pedido es más estrecho y mantenible que crear campos numerados dependientes de configuración manual en eDesk.
