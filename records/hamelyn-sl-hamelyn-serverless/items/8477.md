## Label Justifications

- `P1`: La gestión actual de roles puede ampliar privilegios administrativos a usuarios de logística en un flujo interno activo.
- `impact:security`: La issue trata una frontera de autorización y la asignación de roles con acceso a superficies sensibles.

## Summary

La issue sigue siendo necesaria: el código actual permite que `admin-logistic` gestione roles, mientras el menú oculta Usuarios, y la reasignación segura requiere confirmar cada excepción operativa.

## What This Changes

Auditar los roles del panel Admin, reasignar cuentas con privilegios excesivos y alinear los paneles y APIs con el principio de mínimo privilegio.

## Best Possible Solution

Definir el roster aprobado y el mapa de permisos, restringir la administración de roles a una frontera explícita y aplicar las reasignaciones con una comprobación operativa posterior.

Options:

- **Limitar Usuarios a administradores (recommended):** Restringir GET, POST y PUT de Usuarios a `admin-user` y conservar para logística solo las superficies operativas documentadas.
- **Separar lectura y edición:** Permitir una consulta mínima a logística, pero prohibir crear usuarios y asignar o retirar roles mediante una política diferenciada.
- **Mantener la frontera actual:** Aceptar que `admin-logistic` administra usuarios y documentarlo como privilegio operativo explícito.
