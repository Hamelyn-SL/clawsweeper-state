## Label Justifications

- `P1`: La rama puede publicar feeds de Google Merchant con datos de producto sustancialmente desactualizados.
- `merge-risk: 🚨 compatibility`: Cambia por defecto de lecturas Mongo en vivo a un snapshot diario para campos que determinan el contenido del feed.
- `merge-risk: 🚨 availability`: La retirada del cron depende de que dos jobs externos se apliquen correctamente después del merge.

## Summary

La migración es valiosa, pero no es segura para mergear aún: la ruta BigQuery usa metadatos de producto materializados diariamente sin proteger su frescura, mientras los feeds se despachan cada tres horas.

## What This Changes

La rama mueve los feeds usados de Google Merchant a BigQuery, añade rollback a Mongo y sustituye los cron de GitHub por dos dispatches de Cloud Scheduler.

## Best Possible Solution

Mantener una garantía explícita de frescura para los datos de producto antes de activar BigQuery por defecto, y desplegar los dos jobs de Cloud Scheduler de forma coordinada antes de retirar el cron nativo.
