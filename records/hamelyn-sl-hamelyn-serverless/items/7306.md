## Summary

Mantener abierta: `dev` todavía consulta `config` únicamente por `name`, por lo que puede seleccionar el documento `DEV` y reproducir el LWA 401. La PR enlazada está abierta, es mergeable y contiene la corrección acotada sobre el helper actual, pero sigue en borrador y aún no ha aterrizado.

## What This Changes

La issue solicita que `marketplace_api` seleccione las credenciales `PROD` de Amazon COM y exponga `sellerId` para que las validaciones read-only de SP-API no fallen con LWA 401.

## Best Possible Solution

Aterrizar la PR enlazada conservando la caché, el single-flight y los reintentos actuales, y verificar tras el despliegue que Amazon COM obtiene 200 en `/sellers/v1/marketplaceParticipations` y que un placeholder `{{cred:sellerId}}` se resuelve desde `merchantId`.

## Maintainer Decision

Required: false

## Reproduction Assessment

Sí. La investigación live reprodujo 401 `invalid_client` con el documento `DEV` y obtuvo LWA 200 más respuesta 200 de SP-API con `PROD`; el código actual de `dev` conserva la selección ambigua que permite ese recorrido.

## Solution Assessment

Sí. Filtrar por `environment: "PROD"`, calcular el alias `sellerId` antes de cachear y usar el mismo entorno al persistir el refresh de MercadoLibre corrige la causa en el único helper que carga estas credenciales, sin duplicar el flujo de autenticación.
