## Summary

El problema sigue siendo necesario: `dev` aún tiene el cron con límite de 60 minutos y la etapa `fichas` puede acumular fallos por autor sin hacer fallar la etapa completa. Además no hay PR abierto que cierre este trabajo.

## What This Changes

El issue pide corregir el cron semanal de enriquecimiento de autores con Wikidata para que no timeout, propague fallos reales, consolide duplicados de `authorId` y deje un índice único efectivo en producción.

## Best Possible Solution

Hacer un plan de reparación en dos fases: primero cambiar el cron para propagar fallos y acotar el runtime, y después ejecutar una consolidación auditada de autores duplicados con creación verificada del índice único.

Options:

- **Backfill auditado con ficha canónica (recommended):** Elegir una ficha canónica por `authorId`, conservar o redirigir slugs heredados y crear el índice único solo tras un dry-run con muestras.

## Solution Assessment

No hay una solución ya aplicada en `dev`. La vía mantenible es combinar un parche del cron con una migración/backfill auditada, no limitarse a subir el timeout.
