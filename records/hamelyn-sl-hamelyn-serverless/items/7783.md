## Summary

El PR aborda un fallo real de pérdida de incidencias, pero todavía rompe clientes existentes ante respuestas diferidas y deja varios checkpoints persistidos sin recuperación segura. Debe corregirse y demostrar el flujo real antes de integrarlo.

## What This Changes

Añade un outbox MongoDB y un cron de recuperación para diferir y reintentar incidencias de eDesk cuando falla la entrega síncrona.

## Best Possible Solution

Mantener el outbox como dueño único de cada incidencia, propagar explícitamente el estado diferido en las interfaces y hacer reintentables los checkpoints de ticket y pedido antes de borrar el payload.
