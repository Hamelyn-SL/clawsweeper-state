## Label Justifications

- `P1`: Los 429 agotados pueden dejar stocks de Amazon en `SYNC_ERROR` sin recuperación en el siguiente ciclo.
- `impact:other`: El impacto confirmado está en la sincronización de catálogo y creación de listings de marketplace.

## Summary

La incidencia sigue siendo necesaria: `dev` limita las llamadas conocidas, pero aún convierte los chunks de Catalog API agotados por 429 en ASIN ausentes con política STALE. Hay una reparación abierta y vinculada que cubre ese comportamiento pendiente.

## What This Changes

Evitar que un 429 agotado de Amazon Catalog se registre como `No ASIN found for this EAN` y deje stocks sin reintento automático.

## Best Possible Solution

Revisar y fusionar una corrección que marque solo los chunks agotados por 429 como TRANSIENT, manteniendo el caso de ASIN inexistente como STALE; medir después si aún hace falta cuota distribuida.

## Maintainer Decision

## Reproduction Assessment

Sí. El código actual permite seguir el recorrido: un 429 agotado termina como `failedIds`, se descarta y después se convierte en un error STALE de ASIN ausente.

## Solution Assessment

Sí. Diferenciar throttling agotado de ausencia genuina conserva el contrato actual y permite reintentar solo el caso recuperable.
