## Label Justifications

- `P2`: El throttling es recurrente y merece seguimiento, pero la evidencia específica disponible muestra recuperación correcta sin fallo terminal de catálogo.
- `impact:other`: Una saturación persistente de Catalog API puede degradar el enriquecimiento de ASINs y la publicación en Amazon, sin encajar en las demás categorías de impacto.

## Summary

Conviene mantener abierta esta canónica: el cambio fusionado redujo llamadas duplicadas, pero el throttling reapareció después y el limitador actual sigue siendo local a cada proceso. La evidencia observada aún muestra recuperación correcta, por lo que falta acordar un umbral operativo antes de plantear otro cambio de código.

## What This Changes

Investigar y reducir los 429 de Amazon COM Catalog API durante la resolución de ASINs, evitando que el agotamiento de cuota termine degradando la creación de listings.

## Best Possible Solution

Tratar los 429 recuperados como una métrica operativa y escalar solo cuando superen un umbral acordado o produzcan errores terminales; si ocurre, centralizar el presupuesto por operación y marketplace, respetar `Retry-After` y validar que los ASINs afectados se recuperan sin marcar stocks como error.
