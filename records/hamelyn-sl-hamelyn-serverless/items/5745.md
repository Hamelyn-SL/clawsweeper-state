## Summary

Conviene mantener abierta esta canónica: el arreglo fusionado redujo llamadas duplicadas, pero la señal reapareció después y el código actual solo limita cada proceso de forma aislada. La evidencia aportada sigue mostrando recuperación correcta, así que no hay todavía una reparación adicional suficientemente demostrada para automatizar.

## What This Changes

Investigar y reducir los `429` recuperables de Amazon Catalog API durante la resolución de ASINs en los crons de marketplace.

## Best Possible Solution

Mantener el backoff y la deduplicación actuales, medir intentos agotados, latencia, marketplace e invocación y, solo si existe impacto terminal, aplicar una solución estrecha como escalonar crons, reducir la tasa efectiva o coordinar la cuota entre instancias; el watcher debería alertar por agotamiento o impacto, no por un primer retry recuperado.
