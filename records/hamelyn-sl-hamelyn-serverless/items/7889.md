## Label Justifications

- `P0`: La autorización actual permite a terceros leer, alterar o asociar carritos activos mediante valores proporcionados por el cliente.
- `impact:security`: El problema afecta directamente al límite de posesión e identidad de una API pública de carrito.

## Summary

Mantener abierta: `dev` sigue permitiendo operar sobre carritos Supply con identificadores controlados por el cliente, sin una prueba de posesión ni identidad derivada del servidor.

## What This Changes

La issue solicita proteger el carrito de Supply con un capability token y eliminar el uso de `userId` del cliente para leer, modificar o fusionar carritos.

## Best Possible Solution

Introducir un contrato único de secreto de carrito en `public` y `core`: hash persistido, verificación timing-safe, 404 uniforme, merge autenticado y una transición con fecha de corte; después adaptar todas las llamadas de Supply.
