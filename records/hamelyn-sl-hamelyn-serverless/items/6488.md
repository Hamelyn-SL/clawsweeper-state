## Summary

Keep open: current `dev` still has the Auth0 provider-tree mismatch, so the GA4 `user_id` and custom user property setters remain wired to a pre-provider `useAuth()` consumer.

## What This Changes

The issue asks to fix Supply analytics identity so GA4/BigQuery receive `user_id` and custom user properties after login.

## Best Possible Solution

Move the Auth0 provider boundary so every auth-dependent analytics identity effect is a descendant of `HamelynAuth0Provider`, then validate with an internal Supply build, GA4 DebugView, BigQuery export, and the GA4 Reporting Identity setting.

Yes, source inspection gives a high-confidence path: `RootLayoutNav` consumes Auth0 context before rendering the provider, so the identity effects are wired to the default context. I did not run a device build or query live BigQuery in this read-only review.

## Solution Assessment

Yes, moving `HamelynAuth0Provider` to wrap the consumer is the narrowest maintainable code fix because it also unblocks `setAnalyticsUserProperties` and `syncTokenAndIdentity`. The GA4 Admin setting remains an operational validation step, not a reason to leave the code bug unresolved.
