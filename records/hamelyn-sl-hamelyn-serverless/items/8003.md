## Label Justifications

- `merge-risk: 🚨 compatibility`: La caché propuesta puede sustituir una actualización inmediata por hasta 24 horas de contenido obsoleto cuando falle la purga.

## Summary

Gracias por la contribución: el cambio ataca el consumo excesivo de KV, pero el TTL de respaldo de 24 horas puede dejar una promo ya guardada desactualizada durante un día si falla la purga de un storefront. Además, falta prueba real del flujo completo.

## What This Changes

El PR cachea por locale las lecturas del KV de Promo Strip, purga la caché de cada storefront tras guardar desde Admin y muestra los fallos parciales de revalidación.

## Best Possible Solution

Usar un TTL de respaldo corto, coherente con la ventana esperada de la incidencia, conservar la advertencia de fallos parciales y aportar evidencia redactada de caché, purga y `401` con el KV operativo.

Sí, desde código se puede seguir la lectura KV por render SSR del layout; no se ha ejecutado contra un KV recuperado para observar el fallo y la mejora reales.

## Solution Assessment

No del todo: cachear e invalidar es una vía mantenible, pero el TTL de 24 horas no encaja con la ventana corta esperada cuando falla una purga remota.
