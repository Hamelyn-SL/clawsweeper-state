## Label Justifications

- `P1`: Un flujo vivo de checkout en Supply Android recibe un 501 por un rechazo funcional conocido de la mensajera.
- `impact:ux-friction`: Supply muestra el error del API mediante un toast genérico porque la respuesta actual no incluye un `errorCode` recuperable.

## Summary

La issue sigue siendo necesaria: el rechazo funcional de Celeritas todavía lanza una excepción y la ruta lo convierte en 501, pese a que Supply ya admite códigos de error explícitos.

## What This Changes

Distinguir el rechazo funcional `Routing not found` de un payload inválido de Celeritas para evitar un 501 genérico durante el drop-off.

## Best Possible Solution

Modelar éxito, rechazo funcional y payload inválido en el límite de Celeritas; devolver un `errorCode` estable y traducido por Supply, conservando el 501 solo para fallos realmente inesperados.
