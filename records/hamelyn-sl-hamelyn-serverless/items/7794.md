- `merge-risk: 🚨 other`: Las carreras pueden dejar en el cuerpo de una PR un estado de prueba correspondiente a otra ejecución.

## Summary

La PR aborda una incidencia real, pero deja carreras entre ejecuciones que pueden publicar feedback para un head distinto y no cumple su promesa de cancelación en pushes rápidos.

## What This Changes

La PR convierte el Proof Agent en un flujo HTTP 202 en segundo plano, separa su job de `pr-lifecycle` y publica estados de prueba en el cuerpo de cada PR.

## Best Possible Solution

Asociar cada ejecución al `headSha` aceptado, impedir cualquier escritura terminal para otro head y demostrar el flujo con dos pushes rápidos antes de integrar.

## Reproduction Assessment

Sí, a nivel de código: acepta un head, hace push antes de `after()` y observa que el callback vuelve a leer la PR sin conservar el SHA inicial.

## Solution Assessment

No todavía: responder HTTP 202 es razonable, pero la solución debe preservar la identidad del head y no limitarse a cancelar el cliente de Actions.
