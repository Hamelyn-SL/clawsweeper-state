## Summary

La rama aborda una incidencia real, pero dos carreras entre ejecuciones pueden sustituir el feedback del head nuevo por estados de una ejecución anterior. Debe corregirse antes de mergear.

## What This Changes

La rama separa el Proof Agent en un job propio, responde HTTP 202 tras publicar `EN CURSO` y ejecuta la prueba en `after()` con nuevos estados de feedback.

## Best Possible Solution

Conservar el `headSha` aceptado en todo el callback y condicionar cada escritura terminal a ese SHA; solo el run vigente debe poder sustituir el bloque de prueba.

## Maintainer Decision

Required: false

## Reproduction Assessment

Sí. Dos invocaciones solapadas con un push entre ellas reproducen por código las escrituras obsoletas: el primer run puede finalizar después de que el segundo publique `running`.

## Solution Assessment

No. La separación con HTTP 202 es razonable, pero debe mantener la identidad del head aceptado hasta todos los resultados terminales y rechazar escrituras antiguas.
