## Label Justifications

- `P2`: Es una mejora operativa concreta para reducir reembolsos y consultas de soporte, pero no corrige una regresión ni bloquea el flujo de pedidos actual.
- `impact:ux-friction`: Los clientes y Atención al Cliente carecen de una vía directa para identificar la oficina de recogida, lo que genera incertidumbre y trabajo de soporte evitable.

## Summary

Debe seguir abierta: `dev` no carga el listado de oficinas ni muestra una oficina de Correos para los pedidos Postlibri. El repositorio ya ofrece almacenamiento PUDO y consulta por código postal, lo que reduce el trabajo, pero falta decidir la superficie operativa y la política de actualización de los datos.

## What This Changes

Se solicita importar 4.281 oficinas de Correos con código postal único y consultar su dirección, horario y teléfono desde el código postal del cliente para gestionar incidencias Postlibri.

## Best Possible Solution

Reutilizar `pudoPoints` con `provider: Carrier.CORREOS`, normalizar el código postal y resolver la oficina de forma calculada en el detalle de OrderSell de admin solo para Postlibri, sin copiar datos potencialmente obsoletos al cliente o al pedido; la carga inicial debe validarse como proceso one-time no versionado y quedar acompañada de una política explícita de refresco.
