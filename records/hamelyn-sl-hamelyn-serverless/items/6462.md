## Summary

La issue debe seguir abierta: las piezas existentes son precedentes parciales y no cubren la base curada anonimizada, el ciclo general de sandboxes, la sincronización de índices ni la detección de drift. Antes de implementar hace falta una decisión humana sobre acceso, PII, permisos y operaciones destructivas.

## What This Changes

La issue solicita una estrategia mantenible para una base MongoDB de desarrollo curada, anonimizada y clonable en sandboxes desechables, con auditoría de drift e índices y guardas anti-producción.

## Best Possible Solution

El estado objetivo debería ser una librería común de guardas, una `Hamelyn_DEV_BASE` inmutable y anonimizada con procedencia declarada, comandos idempotentes para crear y borrar sandboxes de forma segura, y checks separados de índices y drift con documentación operativa.
