## Summary

La iniciativa sigue siendo necesaria: `dev` solo contiene un auditor local y una sandbox limitada a fulfillment, no una base curada anonimizada ni tooling general seguro para clonar, borrar y vigilar sandboxes. La manipulación de datos derivados de producción y operaciones destructivas requiere una decisión explícita sobre seguridad y operación antes de implementarla.

## What This Changes

Crear una estrategia y tooling para una base de desarrollo ligera, anonimizada y reproducible con sandboxes MongoDB desechables, sincronización de índices y detección de drift.

## Best Possible Solution

Definir primero una política de datos y operaciones aprobada, y después construir un paquete reutilizable que genere manifests sin valores, cree y destruya únicamente bases allowlisted, aplique anonimización verificable e informe del drift e índices críticos.
