## Label Justifications

- `P1`: El PR afecta telemetría BL y rutas operativas de shipping con defectos confirmados que harían incorrecto el dashboard tras el despliegue.
- `merge-risk: 🚨 compatibility`: Al mezclar BL-ID de reglas distintas, los consumidores del grafo y de `bl_invocations` recibirían métricas incompatibles con las specs publicadas.
- `merge-risk: 🚨 security-boundary`: Las rutas nuevas llaman al helper de autorización pero convierten fallos de auth en respuestas 500/404 en vez de conservar el 403 establecido.
- `merge-risk: 🚨 availability`: El PR toca muchas rutas calientes de shipping y añade lectura de docs/BigQuery en runtime, por lo que los fallos pueden dejar el dashboard o diagnósticos BL inutilizables.

## Summary

Mantener abierto: el PR aporta una dirección útil para telemetría BL, pero aún no es seguro de mergear porque mezcla BL-ID con reglas distintas, enmascara errores de autorización en endpoints nuevos y la prueba visible no corresponde a la superficie final movida a Data Dashboards.

## What This Changes

El PR añade `logBlEntry`, materialización de invocaciones BL en BigQuery, endpoints y página `/business-logic` en Data Dashboards, y marca specs de shipping con `entryLog`.

## Best Possible Solution

Aterrizar el grafo BL en Data Dashboards con BL-ID fieles a las specs, errores de autorización consistentes y prueba final del flujo real contra BigQuery antes de review humana.
