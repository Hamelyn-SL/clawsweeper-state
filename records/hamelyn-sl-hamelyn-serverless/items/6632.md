## Label Justifications

- `P2`: Es un bug operativo real y reproducible desde fuente, pero la evidencia observada está acotada a dos pedidos y el resto del batch continuó procesándose.
- `impact:other`: Pedidos de marketplace pueden quedar sin confirmación remota de envío y sin una causa persistida que permita recuperarlos o triar el rechazo.

## Summary

La incidencia sigue siendo necesaria: `dev` todavía pierde la causa detallada del fallo de Discogs, marca el lote como `SYNC_ERROR` y rearma los pedidos recientes mediante el recovery; tampoco existe otro issue o PR que posea esta corrección específica.

## What This Changes

Corregir el marcado de pedidos de Discogs como enviados o registrar cada rechazo con información suficiente para aplicar retries y hacer triage sin afectar a pedidos aceptados del mismo lote.

## Best Possible Solution

Hacer que Discogs devuelva un `MarketplaceShipResult` por pedido, con `SHIPPED` o `SYNC_ERROR` y una causa normalizada, usando la persistencia individual ya existente y reservando el corte terminal para firmas confirmadas como no recuperables.

## Maintainer Decision

Required: false

## Reproduction Assessment

Sí, a nivel de fuente con alta confianza: un fallo de `editOrder(..., { status: "Shipped" })` termina en un `SYNC_ERROR` sin motivo, y el cron diario lo rearma mientras sea reciente. No se ha reproducido contra la API real ni se conserva el HTTP original de los dos pedidos.

## Solution Assessment

Sí, devolver resultados individuales y persistir el motivo es la solución más estrecha y coherente con el contrato existente. Excluir todos los errores de Discogs del recovery no sería seguro hasta identificar firmas permanentes mediante evidencia real.

## Repair Work Prompt

Corrige el flujo de envío de Discogs sin cambiar la política global de recovery. Haz que `setAsShippedDiscogs()` devuelva un `MarketplaceShipResult` por cada `OrderSell`: `SHIPPED` cuando `editOrder()` sea aceptado y `SYNC_ERROR` con un motivo normalizado que incluya el `orderId` y el error remoto cuando falle. Evita lanzar un error agregado que convierta todo el lote en fallo y conserva la serialización y el rate limit del cliente. Añade cobertura focalizada si puede hacerse con el runner de tests existente; si la verificación requiere un script one-time, ejecútalo localmente mediante `pnpm exec tsx` y no lo versiones. No añadas configuración, no cambies el recovery de otros marketplaces y no declares firmas permanentes de Discogs sin evidencia. No se requiere editar `CHANGELOG.md`.
