## Summary

El PR aborda un desfase real, pero el filtro global `ACTIVE` oculta errores de retirada aún reintentables y también mezcla los pendientes fuera del desglose anunciado; necesita corrección antes de integrar.

## What This Changes

El PR añade un desglose `syncError` al endpoint v6 y cambia el informe de errores para contar solo `SYNC_ERROR` con stock `ACTIVE`.

## Best Possible Solution

Separar errores accionables por estado: conservar pendientes y retiradas reintentables, excluir solo retirados obsoletos con un criterio explícito, y aplicar un límite seguro a cada consulta no indexada.

## Reproduction Assessment

Sí, a nivel de código: una fila `WITHDRAWN` con `SYNC_ERROR/WITHDRAWNING` transitorio entra en el selector de reintento pero el nuevo filtro del informe la descarta. También existen filas `PENDING_SKYPOD` con `SYNC_ERROR`.

## Solution Assessment

No; usar únicamente `ACTIVE` no implementa la exclusión de retirados que anuncia el cambio, porque también oculta pendientes y retiradas reintentables. Hace falta clasificar los casos accionables de forma explícita.
