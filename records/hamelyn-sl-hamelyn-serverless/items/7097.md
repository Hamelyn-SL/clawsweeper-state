## Summary

La incidencia sigue siendo necesaria: `dev` todavía asigna direcciones y métodos de cobro directamente por índice sin comprobar que la posición exista, mientras las eliminaciones adyacentes sí rechazan índices negativos o fuera de rango. La extracción BL ya fusionada documentó expresamente esta divergencia sin cambiar el comportamiento, por lo que no hay una implementación actual que permita cerrar la incidencia.

## What This Changes

Rechazar las actualizaciones de dirección y método de cobro cuando el índice no identifica un elemento existente, igual que las operaciones de borrado.

## Best Possible Solution

Aplicar en `user.repository/mutations.ts` las mismas guardas de rango ya usadas al borrar, devolver los errores establecidos para cada colección y añadir una verificación write-path para ambos flujos; después, actualizar la spec BL para reflejar el comportamiento corregido.
