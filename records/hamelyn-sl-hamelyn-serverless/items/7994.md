## Label Justifications

- `P1`: Un fallo del gate de evidencia puede bloquear merges legítimos o aprobar evidencia insuficiente en flujos activos.
- `merge-risk: 🚨 security-boundary`: La rama modifica tokens de GitHub App y permite una ruta de evidencia que no valida instrucciones ejecutables.
- `merge-risk: 🚨 availability`: El cierre sin `merge_commit_sha` puede no cancelar ni reconciliar una ejecución de Proof ya iniciada.
- `merge-risk: 🚨 automation`: El workflow `pull_request_target` y el check que condiciona merges cambian de forma amplia.

## Summary

La rama aborda un problema real del gate de PR Proof, pero conserva dos rutas que pueden dejar evidencia insuficiente o estado sin reconciliar; además, la prueba autoritativa vigente sigue siendo `NO CONCLUYENTE`.

## What This Changes

La rama endurece PR Proof con estado v2, ledger y check dedicado, tokens de GitHub App por rol, reconciliación y nuevos verificadores diferenciales.

## Best Possible Solution

Limitar `text-delta` a documentación inequívocamente no ejecutable, derivar la barrera de cierre del último estado autoritativo y demostrar en staging un canario `FALLO → CORRECTO` antes de exigir el check.
