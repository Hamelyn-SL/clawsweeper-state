## Label Justifications

- `P2`: This is a bounded business-logic bug in seller profile address normalization with limited blast radius, not a site-wide emergency.
- `impact:data-loss`: A seller-provided address province/state value is silently discarded for DE/FR instead of being persisted.

## Summary

Keep open: current dev still wipes any supplied province for DE/FR profile addresses, and the related BL PR documents/tests the current behavior as a known divergence rather than fixing it.

## What This Changes

Preserve supplied `state || province` for DE/FR seller profile addresses, leave it blank only when absent, and update the BL-buying-account-11 spec/test with the fix.

## Best Possible Solution

Update the active BL-buying-account PR or a replacement so DE/FR addresses store `state || province` when supplied, leave province blank only when absent, and revise the BL-11 spec/test in the same change.

## Maintainer Decision

## Reproduction Assessment

Yes. Source inspection shows DE/FR go through `isProvinceOptionalCountry` and force `province = ""`, and the related BL PR’s extracted function preserves the same branch.

## Solution Assessment

Yes. The narrow maintainable fix is to change the province resolver to keep `state || province` for optional-province countries without falling back to locality, then update the BL-11 spec and tests beside that behavior.
