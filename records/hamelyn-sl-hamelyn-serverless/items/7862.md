## Label Justifications

- `P1`: La degradación amplifica errores y reconexiones en un bootstrap Mongo compartido por varios servicios productivos.
- `impact:other`: El efecto principal es degradación transversal de disponibilidad de infraestructura, sin evidencia de pérdida de datos ni crash loop.

## Summary

La incidencia sigue siendo necesaria: `dev` aún refresca Mongo en cada reutilización warm y recicla el pool si supera el timeout; la PR relacionada quedó cerrada sin merge y además no preservaba el enriquecimiento autenticado de Analytics Supply.

## What This Changes

Evitar que el refresco de configuración Mongo provoque reconexiones masivas y desacoplar de forma segura el endpoint Supply Analytics de la inicialización de Mongo.

## Best Possible Solution

Mantener cold start estricto y añadir TTL, single-flight y stale-on-error solo para refresh warm; después desacoplar Analytics mediante un flujo que conserve explícitamente el contrato de identidad autenticada.
