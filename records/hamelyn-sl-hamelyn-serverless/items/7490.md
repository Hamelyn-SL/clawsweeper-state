## Label Justifications

- `P2`: Es una mejora de infraestructura planificable y actualmente desactivada; los riesgos bloquean el merge, pero no constituyen una regresión activa en producción.
- `merge-risk: 🚨 security-boundary`: El PR ejecuta código no confiable en sandboxes, introduce credenciales en esa VM y publica artefactos derivados del repositorio privado con acceso público.
- `merge-risk: 🚨 automation`: Varias rutas pueden omitir cambios, impedir `barrier`, perder evidencia o publicar un veredicto correcto sin una comparación válida.

## Summary

La automatización no existe en `dev` y la idea sigue siendo útil, pero el head actual no es mergeable: puede publicar datos derivados de un repositorio privado en Blob público, introduce un token de GitHub dentro del sandbox que ejecuta código no confiable, permite eludir el filtro del driver generado y contiene varios caminos que producen evidencia incorrecta o incompleta. Además, la prueba funcional completa solo se afirma fuera de banda y no hay artefactos inspeccionables del head actual.

## What This Changes

El PR añade dos workflows y un runner que clasifica pull requests, ejecuta modos `gif`, `card` o `barrier` en Vercel Sandbox y actualiza el cuerpo del PR con la evidencia generada.

## Best Possible Solution

Mantener el flujo desactivado y rediseñar la frontera antes de mergear: artefactos privados o URLs autenticadas y temporales, ningún token persistente dentro de la VM no confiable, dependencias bloqueadas y reproducibles, ejecución del driver con aislamiento verificable en vez de regex, estados fail-closed que nunca afirmen éxito sin baseline y runs reales enlazados para `gif`, `card` y `barrier`.
