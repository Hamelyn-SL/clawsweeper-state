## Label Justifications

- `P1`: El PR automatiza sobre todas las contribuciones una ruta capaz de exponer credenciales, publicar evidencia obsoleta o emitir resultados incorrectos.
- `merge-risk: 🚨 security-boundary`: La VM que ejecuta código del PR conserva un token de GitHub y recibe una credencial del AI Gateway, además de publicar artefactos públicos.
- `merge-risk: 🚨 automation`: El nuevo step se ejecuta automáticamente y puede publicar sobre un head distinto, perder evidencias o fallar por límites de tiempo.

## Summary

Debe mantenerse abierto: la funcionalidad no existe en `dev` y este PR sigue siendo su implementación candidata, pero el head actual conserva bloqueos de seguridad y corrección, carece de prueba real inspeccionable y necesita una decisión humana sobre la frontera de ejecución automática.

## What This Changes

Añade un proof-agent que clasifica cada PR, ejecuta pruebas GIF, card o barrier mediante Vercel Sandbox y publica la evidencia en el cuerpo del PR.

## Best Possible Solution

Mantener el agente en modo piloto manual hasta separar el plano de control privilegiado de la VM no confiable, usar artefactos privados, fijar el grafo ejecutable, vincular cada publicación a un SHA inmutable y hacer fail-closed cualquier prueba sin baseline válido.
