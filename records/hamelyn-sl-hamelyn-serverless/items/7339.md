## Summary

La PR sigue siendo necesaria: `dev` solo añadió la retirada de mk docs cuyo stock maestro está `WITHDRAWN`, mientras esta rama cubre la cohorte distinta con stock maestro `ACTIVE` y listing remoto vivo. La implementación es coherente y las revisiones automáticas no detectan defectos nuevos, pero la rama no es mergeable por conflictos con cambios recientes de `dev` y continúa sin prueba real posterior al cambio, por lo que debe permanecer abierta para resolución y validación humana.

## What This Changes

La PR añade una query y un recovery de TodoColeccion que verifican el listing remoto y normalizan a `ACTIVE` los mk docs activos con `UPLOADING_ERROR` vacío cuando el id, el estado y el stock coinciden.

## Best Possible Solution

Integrar manualmente la reconciliación para la cohorte `stockStatus=ACTIVE` junto a la retirada ya vigente para `stockStatus=WITHDRAWN`, preservando el recovery de precio actual de `dev`, y validar con una ejecución live redactada que muestre cada resultado relevante.
