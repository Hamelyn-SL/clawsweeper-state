## Summary

La incidencia sigue siendo necesaria: en `dev` la selección de stocks para alta de marketplace carga el maestro por `_id` sin exigir `StockStatus.ACTIVE`, y la confirmación marca la fila como activa sin revalidar el maestro. Hay una PR abierta con cierre explícito para este problema, así que la issue debe permanecer abierta hasta revisar y aterrizar o cerrar esa PR.

## What This Changes

La issue pide bloquear que el pipeline de creación/confirmación de marketplace publique o reactive listings cuando el stock maestro ya está vendido o `WITHDRAWN`.

## Best Possible Solution

Mantener esta issue abierta y usar la PR vinculada como candidata de implementación; el cierre correcto debería ocurrir cuando se mergee el guard en `dev` y se ejecute por separado la limpieza operativa del acumulado.
