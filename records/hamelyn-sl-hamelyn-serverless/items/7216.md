## Summary

Current dev still models per-product review metadata as acceptance metadata, and the issue remains necessary because rejected products lose reviewer/time traceability. The related epic is open and this subtask is assigned, so this should stay open for the Admin/core/data-platform implementation and historical-data decision.

## What This Changes

Request to replace per-product `acceptedAt`/`acceptedBy` semantics with `reviewedAt`/`reviewedBy` so every accept or reject action records the latest reviewer and timestamp.

## Best Possible Solution

Implement the per-product review trace as a coordinated Admin/core/data-platform change with backwards-compatible reads for historical acceptance metadata and an explicit migration or no-backfill decision.

- **Backfill historical accepted products:** Run a controlled backfill that copies accepted metadata into reviewed metadata for old accepted product rows, with no inferred reviewer for rejected rows unless another source is approved.

## Reproduction Assessment

Yes for the current behavior: source inspection shows accepting writes `acceptedBy`/`acceptedAt`, while rejecting clears those fields, so rejected products cannot retain per-product review traceability. This is a feature request rather than a broken documented contract.

## Solution Assessment

Unclear until the historical-data decision is made. The requested `reviewedAt`/`reviewedBy` model is the right end state, but the safest implementation needs compatibility for existing `acceptedAt` consumers and an explicit backfill policy.
