## Summary

La PR aporta una implementación amplia y coherente, pero no está lista para integrar: deja fuera del reparto a quienes aterrizan en `/`, permite HTML no saneado al abrir el editor desde KV y acepta una Main visualmente vacía. También falta prueba real actualizada del flujo Admin→Ecommerce.

## What This Changes

La rama añade una promo strip configurable desde Admin mediante Vercel KV, con contenido por locale, variantes repartidas por visitante y fallback al mensaje i18n actual.

## Best Possible Solution

Mantener el fallback actual, sanear o validar las entradas de KV en el GET antes del editor, exigir texto visible para Main e incluir `/` en la inicialización estable del visitor ID antes de demostrar el flujo completo con credenciales redactadas.
