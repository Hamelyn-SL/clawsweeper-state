## Summary

La issue sigue siendo necesaria: `dev` todavía emite `MERGE` directo contra `hamelyn-data.mongodb.<colección>` sin crear la tabla destino y las colecciones `mk_discogs`, `mk_decathlon` y `mk_alibris` siguen fuera de `MARKETPLACE_COLLECTIONS`. Hay un PR abierto que usa sintaxis de cierre para esta issue, así que lo correcto es mantenerla abierta hasta revisar y aterrizar ese PR.

## What This Changes

La issue pide que `bq-merge` cree automáticamente las tablas raw `mongodb.*` que falten antes de cada `MERGE` y que las nuevas colecciones de marketplace entren en el merge horario.

## Best Possible Solution

Revisar y aterrizar `https://github.com/Hamelyn-SL/hamelyn-serverless/pull/7283`, incluyendo la auto-creación de tablas y el alta de `mk_discogs`, `mk_decathlon` y `mk_alibris`, y cerrar esta issue solo cuando ese cambio esté en `dev`.

## Reproduction Assessment

Sí: por inspección de código en `dev`, basta añadir una colección nueva a `MERGE_COLLECTIONS` sin tabla raw previa para que el SQL generado haga `MERGE` contra una tabla inexistente dentro del único bloque `BEGIN`. ## Solution Assessment

Sí, la ruta propuesta es estrecha y mantenible: crear cada tabla raw con `CREATE TABLE IF NOT EXISTS` justo antes de su `MERGE`, respetando el tipo `JSON` solo para `users` y `offers`. El PR abierto implementa exactamente esa forma y debe revisarse antes de cerrar la issue.
