## Summary

Keep open. Current dev already records Mercado Pago payments in Stripe as off-Stripe payment records, but there is no current code path that initiates or reports refunds, and making Stripe execute refunds requires a payment-flow decision.

## What This Changes

Requested feature: reflect Mercado Pago payments in Stripe so refunds can be operated from Stripe instead of logging into Mercado Pago or Meli.

## Best Possible Solution

Define a unified refund workflow that calls Mercado Pago for the actual refund and records the refund outcome in Stripe, unless maintainers explicitly choose to migrate Mercado Pago checkout to a Stripe-native processor flow.

## Maintainer Decision

Required: true

Kind: product_direction

Question: Should Mercado Pago refunds be operated by a Hamelyn flow that calls Mercado Pago and then reports the refund to Stripe, or should Mercado Pago checkout be migrated so Stripe processes and refunds the payment end to end?

Rationale: Current code proves Stripe is only a reporting surface for these payments, so the implementation depends on whether maintainers want Stripe visibility or Stripe to become the payment processor/refund executor.

Likely owner: JavierHamelyn

Owner reason: JavierHamelyn has the strongest current history on the Mercado Pago checkout and Stripe payment-record integration.

Owner confidence: high

Options:

- **Add Hamelyn refund action (recommended):** Implement a backoffice refund flow that executes the refund in Mercado Pago and records the refund result in Stripe for reconciliation.
- **Migrate to Stripe-native processing:** Rework the payment method so Stripe creates the charge and can execute refunds directly, if the product and provider constraints allow it.
- **Keep Mercado Pago manual refunds:** Keep Stripe as visibility-only and continue operating refunds directly in Mercado Pago or Meli.

## Reproduction Assessment

Not applicable: this is a feature request about payment/refund workflow ownership, not a bug with a failing reproduction path. Source inspection confirms the current architecture records Mercado Pago payments in Stripe but does not provide a refund path.

## Solution Assessment

Unclear until maintainers choose the operating model. The narrowest maintainable solution appears to be a Hamelyn refund action that calls Mercado Pago and reports the result to Stripe, rather than expecting Stripe to refund a payment it did not process.
