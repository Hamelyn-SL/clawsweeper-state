## Summary

Keep this issue open: current dev still builds author descriptions from Wikipedia summaries, still resolves author portraits from Commons/Wikipedia sources, and the ecommerce author page publishes those fields without attribution or stored license metadata.

## What This Changes

The issue reports that public author pages reuse Wikipedia summary text and Commons images without attribution or license metadata.

## Best Possible Solution

Choose a license strategy, preferably generating author descriptions only from CC0 facts and serving only PD/CC0 images or placeholders, then clean/backfill existing author records and keep attribution metadata out of the public page unless the team explicitly chooses the attribution route.

Rationale: Both paths are plausible and affect legal exposure, SEO content, image availability, stored data shape, and public UI; automation should not choose that policy without maintainer intent.

Options:

- **Avoid CC obligations (recommended):** Generate descriptions only from CC0 Wikidata facts, stop storing Wikipedia extracts, and only cache images whose Commons metadata is PD/CC0, using the fallback image otherwise.
- **Keep content with attribution:** Persist source, author, license, license URL, and file/article links, then show attribution on the author page and include appropriate structured-data/source context.
- **Containment first:** Temporarily suppress stored author descriptions/images from the public author page while the final ingestion and data-cleanup path is decided.
