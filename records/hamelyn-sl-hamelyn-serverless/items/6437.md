- `impact:other`: La ausencia de eventos de entrega impide activar de forma fiable el correo de reseña para ventas enviadas mediante estos carriers.

## Summary

La issue sigue siendo necesaria: `dev` solo mantiene ingesta continua de tracking de ventas para Cainiao y Spring, mientras que el polling productivo consulta exclusivamente compras (`Order`). No hay una PR abierta ni otra issue que posea la implementación pendiente para `OrderSell`.

## What This Changes

Sincronizar en `ordersells.trackingEvents` los eventos de entrega normalizados de SEUR, FEDEX y CORREOS para poder detectar la entrega de ventas de Discogs.

## Best Possible Solution

Crear una orquestación de tracking de ventas separada de las políticas de compras, reutilizando el pipeline común, con consulta indexada de `OrderSell`, cadencia persistida, deduplicación, límites por carrier y normalización completa de CORREOS.

## Maintainer Decision

Required: false

## Reproduction Assessment

Sí, con alta confianza a nivel de fuente: una venta con SEUR, FEDEX o CORREOS no entra en ningún polling productivo que persista eventos en `ordersells.trackingEvents`. No se ha ejecutado una reproducción contra APIs reales durante esta revisión de solo lectura.

## Solution Assessment

Sí en dirección general, pero conviene separar la orquestación de ventas de las políticas del cron de compras. Reutilizar consulta, transformación, normalización y deduplicación existentes es más mantenible que añadir tres webhooks específicos sin contrato confirmado.
