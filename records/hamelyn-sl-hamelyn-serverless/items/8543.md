## Label Justifications

- `P1`: Un merge sin preaprovisionamiento puede degradar diariamente el SEO de todo el catálogo al omitir `lastmod`.
- `merge-risk: 🚨 compatibility`: El nuevo fallback reemplaza el comportamiento existente por ausencia de `lastmod` para todas las URLs mientras la tabla no exista.

## Summary

Mantener abierta: el enfoque corrige el problema SEO, pero el corte a la nueva tabla puede eliminar todos los `lastmod` en `dev` antes de que la infraestructura de BigQuery esté aprovisionada.

## What This Changes

La rama añade una tabla diaria de BigQuery para `lastmod` SEO, hace que el generador la consuma, amplía la caché de sitemaps y precalienta los ficheros publicados.

## Best Possible Solution

Aprovisionar y verificar `mongodata.ecommerce_seo_lastmod` desde esta referencia antes de activar el generador en `dev`, o separar ambos pasos para que nunca exista una ventana sin datos de `lastmod`.
