## Label Justifications

- `P0`: Esta PR es el vehículo de reparación para un bloqueo de checkout de compradores anónimos al aplicar una promoción anunciada.
- `merge-risk: 🚨 compatibility`: El nuevo uso directo del ID persistido cambia el comportamiento de instalaciones con valores legacy o corruptos en `localStorage`.

## Summary

La corrección aborda la causa raíz del cupón en carritos anónimos y aporta prueba E2E, pero introduce un bloqueo P1: un `cartId` legacy o corrupto puede hacer que `new Types.ObjectId(cartId)` lance durante la actualización optimista.

## What This Changes

La rama alinea el ID del carrito optimista con el ID persistido y reconcilia el ID devuelto por la API, además de traducir `invalidCartError` en nueve diccionarios de checkout.

## Best Possible Solution

Validar el ID persistido antes de crear el ObjectId optimista, conservar el fallback seguro y confirmar tanto el flujo nuevo como uno con `localStorage.cartId` no válido.

## Solution Assessment

No todavía: reutilizar el ID es la solución correcta, pero debe validar el valor persistido antes de construir un ObjectId para conservar la recuperación existente ante almacenamiento inválido.
