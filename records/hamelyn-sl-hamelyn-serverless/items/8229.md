## Label Justifications

- `P1`: La regresión propuesta puede impedir añadir productos a usuarios con un identificador persistido no válido.
- `merge-risk: 🚨 compatibility`: La PR cambia cómo se interpreta un `cartId` ya guardado en el navegador durante una actualización.
- `merge-risk: 🚨 availability`: El constructor BSON puede lanzar dentro del updater de estado y bloquear el flujo de carrito.

## Summary

La corrección ataca la causa raíz y la prueba E2E aportada cubre el flujo principal, pero introduce un bloqueo P1: un `cartId` legado o corrupto puede lanzar `BSONError` al crear el estado optimista y romper el alta de productos.

## What This Changes

La PR reutiliza el `cartId` persistido para el carrito anónimo optimista, reconcilia el ID devuelto por la API y añade el texto de `invalidCartError` en diccionarios de checkout.

## Best Possible Solution

Validar `cartId` con `Types.ObjectId.isValid` antes de construir el ID optimista y conservar la reconciliación con `response.cartId` cuando el servidor cree o rote el carrito.

## Solution Assessment
