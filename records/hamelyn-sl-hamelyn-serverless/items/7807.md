## Label Justifications

- `P1`: La incidencia mantiene ofertas activas en una cola de precio que reintenta en lotes repetidos y puede retrasar actualizaciones reales.
- `impact:other`: El impacto concreto es la reconciliación incorrecta de la cola de precios de un marketplace, fuera de las clases específicas disponibles.

## Summary

Gracias por el reporte: esta incidencia sigue siendo necesaria. El flujo actual convierte un HTTP 500 del envío Fnac en error para todo el lote, sin poder distinguir ofertas ya aceptadas por Fnac.

## What This Changes

Corregir los reintentos de precio Fnac para reconciliar resultados ambiguos de lotes HTTP 500 y evitar mantener en cola ofertas cuyo precio remoto ya coincide.

## Best Possible Solution

Añadir una reconciliación idempotente con una confirmación oficial de Fnac que confirme solo los SKU observados al precio esperado y deje reintento acotado para los demás.

## Maintainer Decision

Required: true

Kind: product_direction

Question: ¿Qué fuente autoritativa debe decidir si un lote Fnac con HTTP 500 se aceptó parcialmente antes de limpiar `needsUpdatePrice`?

Rationale: El fallo no aporta `batch_id`; escoger entre consulta oficial de oferta, estado de lote o snapshot cambia el contrato de corrección y el riesgo de ocultar precios pendientes.

Likely owner: JavierHamelyn

Owner reason: Su cambio reciente concentra la política de recuperación de precios y su reporte aporta la evidencia operativa de la cohorte.

Owner confidence: high

Options:

- **Confirmación oficial por oferta o lote (recommended):** Usar una consulta autoritativa de Fnac para confirmar únicamente los SKU con el precio esperado y conservar el retry de los no confirmados.
- **Mantener reintentos con backoff:** Conservar la semántica actual, añadiendo límites y alertas, sin limpiar ofertas cuya aceptación sea ambigua.
- **Reconciliar desde el snapshot:** Usar el snapshot de listings como señal diferida, aceptando su latencia y definiendo explícitamente cuándo puede cerrar la cola.

## Reproduction Assessment

Sí, a nivel de fuente: un `mkUpdatePrice` batch que lance HTTP 500 provoca que el catch persista error para todos los SKU válidos. El reporte aporta además una cohorte productiva coherente con esa ruta.

## Solution Assessment

No del todo: el diagnóstico es sólido, pero limpiar por coincidencia remota exige decidir una fuente autoritativa y una regla de consistencia para respuestas ambiguas.
