## Summary

Este PR debe seguir abierto: la dirección del arreglo es correcta, pero el parche todavía puede dejar listings vendidos publicados porque el ramal nuevo no conserva el `marketplaceId`, no trata un maestro inexistente como no activo y hace la entrega al withdraw cron con dos escrituras separadas.

## What This Changes

El PR filtra maestros `ACTIVE` al seleccionar stocks para subir a marketplace, revalida el stock maestro antes de confirmar create/update-price y actualiza la skill `hamelyn-knowledge` con la nueva garantía operativa.

## Best Possible Solution

El arreglo debería confirmar en una operación coherente el estado de retirada pendiente preservando `marketplaceId`, `price` y `productType`, tratar `!master` como no activo, y acompañarlo con una prueba real o transcript redacted del flujo create/update-price hasta que el withdraw cron pueda retirar la fila.
