## Label Justifications

- `P0`: El acceso no autenticado permite manipular o asociar carritos ajenos mediante identificadores aportados por el cliente.
- `impact:security`: La incidencia trata un bypass de autorización y una comprobación de posesión inexistente.
- `impact:data-loss`: Las rutas expuestas permiten alterar o vaciar productos de un carrito que no pertenece al solicitante.

## Summary

Mantener abierta: `dev` sigue aceptando `cartId` y `userId` del cliente como prueba de posesión en las rutas del carrito ecommerce, sin capability token ni autenticación de identidad.

## What This Changes

Incorporar al carrito web un capability token persistido como hash, cookie segura y merge autenticado, coordinado con la protección equivalente de Supply.

## Best Possible Solution

Definir un contrato único de posesión para Supply y Ecommerce, aplicarlo a todas las rutas y consumidores del carrito, y validar tanto el flujo anónimo como el merge autenticado.

## Maintainer Decision

Required: true

Kind: security_boundary

Question: ¿Se aprueba un contrato compartido de capability token para ambos carritos, con transición temporal de anónimos heredados y JWT obligatorio para el merge?

Rationale: La elección de cookie, derivación de identidad y ventana de transición cambia el límite de autorización de dos aplicaciones y requiere aprobación de seguridad.

Likely owner: HamelynDev

Owner reason: Su historial reciente está ligado a la ruta principal afectada y puede coordinar el contrato con el área de seguridad.

Owner confidence: medium

Options:

- **Aprobar contrato compartido (recommended):** Implementar emisión, hash, comparación timing-safe y transición comunes; es la vía recomendada para no duplicar límites de autorización.
- **Separar los despliegues:** Resolver Ecommerce y Supply con contratos independientes si sus ciclos de despliegue exigen ventanas distintas.
- **Pausar para diseño de seguridad:** Documentar primero el contrato de migración y autenticación antes de cambiar rutas en producción.

## Reproduction Assessment

Sí, mediante una petición a las rutas same-origin con un `cartId` conocido y un `userId` elegido; el código actual muestra que no existe verificación de posesión.

## Solution Assessment

Sí, con un ajuste importante: la utilidad debe ser compartida con Supply y proteger también las rutas auxiliares y el merge, no solo la lectura principal.
