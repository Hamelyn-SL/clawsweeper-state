## Label Justifications

- `P0`: La superficie actual permite leer o mutar carritos con datos controlados por el cliente, afectando al límite de autorización.
- `impact:security`: La corrección trata un IDOR y elimina identidad y posesión aportadas por el cliente.

## Summary

Mantener abierta: `dev` sigue permitiendo operar con carritos mediante identificadores aportados por el cliente y la corrección está vinculada a una PR abierta que aún requiere validación de transición y seguridad.

## What This Changes

La issue solicita que ecommerce use una capability en cookie para carritos anónimos y JWT para carritos autenticados, eliminando la confianza en `cartId` y `userId` del cliente.

## Best Possible Solution

Aterrizar un guard único de posesión en ecommerce, con hash persistido, cookie segura, JWT derivado del Bearer y pruebas negativas para cada ruta antes de fusionar la PR vinculada.
