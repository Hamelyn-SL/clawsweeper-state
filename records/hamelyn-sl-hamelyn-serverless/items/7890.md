## Label Justifications

- `P0`: La superficie permite una elusión de autorización sobre lectura, modificación y asociación de carritos de terceros.
- `impact:security`: El problema afecta directamente a la prueba de posesión y a la identidad usada para operar sobre carritos.

## Summary

Mantener abierta: `dev` sigue permitiendo operar sobre carritos de ecommerce con `cartId` y, en varias rutas, con `userId` aportado por el cliente; no existe aún un contrato de posesión ni autenticación que cierre esta superficie.

## What This Changes

La issue solicita proteger el carrito web de ecommerce mediante capability token, cookie segura y merge autenticado derivado del JWT.

## Best Possible Solution

Definir un guard compartido en `@hamelyn/core`, emitir y hashear un secreto por carrito, aplicarlo a todas las rutas y mover el merge autenticado a una identidad derivada del JWT.

## Reproduction Assessment

Sí, a nivel de código con alta confianza: las rutas consumen `cartId` y `userId` del cliente sin un guard de sesión o capability. No se realizaron solicitudes mutantes contra producción.

## Solution Assessment

Sí, con matices: el patrón capability más JWT es el camino mantenible, pero debe cubrir creación, rutas laterales y una transición de upgrade limitada por servidor.
