## Summary

Keep open: current dev still lets coupon prevalidation build its coupon total from client-sent shipping values, and the only focused fix PR was closed unmerged after being labeled size/L.

## What This Changes

The issue asks for coupon prevalidation to recalculate shipping cost and regional surplus server-side instead of trusting ecommerce client payload values.

## Best Possible Solution

Introduce one shared server-side ecommerce shipping calculation in core, use it from coupon prevalidation with only cart/destination/priority accepted from the client, and align it with the broader checkout total validation path.
