## Summary

Keep open: current dev still lets coupon prevalidation read client-sent shipping and regional surplus values, and the only fixing PR was closed unmerged as too large. The related checkout trust-boundary issue at https://github.com/Hamelyn-SL/hamelyn-serverless/issues/6920 overlaps but does not replace this narrower coupon prevalidation bug.

## What This Changes

The issue asks coupon prevalidation to recalculate shipping cost and regional surplus server-side instead of trusting the ecommerce client payload.

## Best Possible Solution

Introduce one shared server-side ecommerce shipping calculation and use it in coupon prevalidation, coordinating the same calculation with checkout amount validation in https://github.com/Hamelyn-SL/hamelyn-serverless/issues/6920.
