## Summary

Mantener abierta: el arreglo inicial está en `dev` para el camino directo, pero la ruta `applyMutations()` todavía puede construir un `bulkWrite.updateMany` con un update pipeline array sin soporte explícito. Eso encaja con la señal posterior de `triage:confirmed-live` y hace prematuro cerrar esta issue como implementada.

## What This Changes

La issue reporta que `processBatch` en CDL, Fnac y Feltrinelli falla cuando un update pipeline llega a Mongo/Mongoose sin habilitar `updatePipeline`.

## Best Possible Solution

Corregir el camino de `applyMutations()` para que las mutaciones pipeline no lleguen a Mongoose como arrays sin soporte explícito, con una prueba de regresión que cubra `completeBatchToNextState()` tanto en update directo como en bulk.

## Repair Work Prompt

Arregla la issue de marketplace-crons sobre `Cannot pass an array to query updates unless the updatePipeline option is set.` después de la PR fusionada https://github.com/Hamelyn-SL/hamelyn-serverless/pull/5310. La inspección actual muestra que `MarketplaceRepository.applyMutation()` ya añade `updatePipeline: true`, pero `MarketplaceRepository.applyMutations()` crea operaciones `bulkWrite.updateMany` con `update: compiled.pipeline` sin soporte explícito. Investiga la compatibilidad real de Mongoose 9 para update pipelines dentro de `bulkWrite`; si se admite una opción por operación, úsala de forma acotada, y si no, separa o ejecuta las mutaciones pipeline por una ruta segura existente. Añade una prueba de regresión para `MarketplaceMutationFactory.completeBatchToNextState()` en el camino bulk y mantén intactos los estados, retries y payloads externos de marketplace. No cambies integraciones específicas de CDL/Fnac/Feltrinelli salvo que la prueba demuestre que la ruta compartida no es el origen.
