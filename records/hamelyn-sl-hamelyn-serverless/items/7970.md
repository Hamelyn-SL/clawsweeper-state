## Summary

Gracias por el contexto: la migración sigue pendiente en `dev`; el export aún abre un cursor completo de Mongo y el workflow no admite BigQuery ni selección de fuente. La evidencia de paridad permite mantenerla como trabajo de plataforma, no cerrarla.

## What This Changes

La issue propone migrar los candidatos del export diario de Alibris a `mongodata.stocks` de BigQuery, con control de frescura y rollback manual a Mongo.

## Best Possible Solution

Añadir un lector BigQuery acotado al export y un workflow con `source=bigquery|mongo`; ante falta de frescura, abortar de forma visible y dejar Mongo como rollback manual.

Options:

- **Abortar y permitir rollback manual (recommended):** Si el marcador no está fresco tras el timeout, fallar el run y exigir un dispatch explícito con `source=mongo`.
- **Aceptar datos stale:** Mantener el comportamiento de la acción compartida y publicar el TSV aunque el snapshot horario esté retrasado.
- **Fallback automático a Mongo:** Cambiar automáticamente a Mongo cuando falte frescura, aceptando que el cron vuelva a cargar el primario en incidentes.

## Reproduction Assessment

Sí, a nivel de código: el run programado invoca el cursor Mongo completo sobre `stocks` con `ACTIVE` y `book`. No se ejecutó contra producción por tratarse de una revisión de solo lectura.

## Solution Assessment

No del todo: el patrón de Flash Offers es reutilizable, pero debe decidirse el tratamiento de un timeout de frescura antes de aplicarlo a un export purge.
